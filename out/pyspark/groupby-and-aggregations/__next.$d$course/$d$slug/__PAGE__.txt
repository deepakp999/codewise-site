<h2 id="window-functions-the-power-tool">Window Functions: The Power Tool</h2>
<p>GroupBy collapses rows — you go from 8 employees to 3 department rows. But what if you want to keep every row AND add information about its group? That's what window functions do.</p>
<p>Think of it this way: groupBy says "tell me about each department." Window functions say "tell me about each employee relative to their department."</p>

<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Calling separate aggregation methods instead of using agg().</strong> <code>df.groupBy("dept").count()</code> followed by <code>df.groupBy("dept").avg("salary")</code> triggers two shuffles. Use <code>df.groupBy("dept").agg(count("*"), avg("salary"))</code> for one shuffle.</li>
<li><strong>Expecting ordered output from groupBy.</strong> PySpark groupBy results are unordered. If you need sorted output, always add <code>.orderBy()</code> explicitly.</li>
<li><strong>Using a window with orderBy when you don't need ordering.</strong> For simple aggregations like department average, use <code>Window.partitionBy("department")</code> without <code>.orderBy()</code>. Adding orderBy changes the behavior — it makes <code>sum()</code> compute a running total instead of a grand total.</li>
<li><strong>Confusing rank, dense_rank, and row_number.</strong> Use <code>row_number</code> when you need unique sequential numbers. Use <code>rank</code> when ties should share the same position. Use <code>dense_rank</code> when you want no gaps after ties.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li><code>groupBy().agg()</code> collapses rows into group summaries — always use <code>agg()</code> for multiple aggregations to minimize shuffles.</li>
<li>Window functions keep every row but add group-level calculations as new columns.</li>
<li>Define windows with <code>Window.partitionBy()</code> (like groupBy) and optionally <code>.orderBy()</code> (for rankings and running totals).</li>
<li><code>row_number</code>, <code>rank</code>, and <code>dense_rank</code> handle ties differently — choose intentionally.</li>
<li>Window functions without <code>orderBy</code> give you the full group aggregate; with <code>orderBy</code> they give running/cumulative results.</li>
</ul>
