<div data-cw-section="learn-box"><h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>How to define a schema using StructType and StructField</li>
<li>All the common PySpark data types and when to use them</li>
<li>Why explicit schemas are 2-3x faster than inferSchema</li>
<li>How to check and enforce your schema at read time</li>
</ul>
</div><h2 id="the-problem-with-inferschema">The Problem with inferSchema</h2>
<p>In the last lesson, we read a CSV with <code>inferSchema=True</code>. It worked, but here's what actually happened:</p>
<ol>
<li>Spark read the <strong>entire file once</strong> just to guess the data types</li>
<li>Spark read the <strong>entire file again</strong> to actually load the data</li>
<li>Spark guessed wrong on some columns (treating zip codes as integers, for example)</li>
</ol>
<p>On a 10 GB CSV, that's 20 GB of I/O instead of 10 GB. On a 100 GB file, it's painfully slow. And the guesses aren't always right.</p>

<p>Let's break down each part:</p>
<ul>
<li><code>StructType([...])</code> — defines the overall table structure, like a list of column definitions</li>
<li><code>StructField("name", StringType(), nullable=False)</code> — one column: its name, its type, and whether it allows null values</li>
<li><code>nullable=False</code> — Spark will flag an error if this column contains null values</li>
</ul>
<h2 id="common-data-types">Common Data Types</h2>
<p>Here are the PySpark data types you'll use most often:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">from</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> pyspark.sql.types </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">import</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> (</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    StringType,      </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Text: "Alice", "Engineering"</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    IntegerType,     </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Whole numbers: 1, 42, -100 (32-bit)</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    LongType,        </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Large whole numbers (64-bit, Spark's default for integers)</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    DoubleType,      </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Decimal numbers: 3.14, -0.001 (64-bit)</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    FloatType,       </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Decimal numbers (32-bit, less precision)</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    BooleanType,     </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># True or False</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    DateType,        </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Date only: 2024-01-15</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    TimestampType,   </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Date + time: 2024-01-15 14:30:00</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    DecimalType,     </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Exact decimals for financial data: DecimalType(10, 2)</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    ArrayType,       </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># List of values: [1, 2, 3]</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    MapType,         </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Key-value pairs: {"a": 1, "b": 2}</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)</span></span></code></pre>
<p><strong>A practical rule:</strong> Use <code>StringType</code> for anything that shouldn't be calculated with (names, IDs, zip codes, phone numbers). Use <code>IntegerType</code>/<code>LongType</code> for countable things. Use <code>DoubleType</code> for measurements. Use <code>DecimalType</code> for money.</p>

<p>In production, start with <code>FAILFAST</code> during development to catch issues early, then switch to <code>PERMISSIVE</code> with a <code>_corrupt_record</code> column for monitoring in production.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Using <code>IntegerType</code> when Spark infers <code>LongType</code>.</strong> When Spark infers schemas, it defaults to <code>LongType</code> for whole numbers. If you define <code>IntegerType</code> in your schema but the values exceed 2.1 billion, you'll get nulls or errors. When in doubt, use <code>LongType</code>.</li>
<li><strong>Treating zip codes and phone numbers as integers.</strong> Zip code <code>07001</code> becomes <code>7001</code> as an integer — you lose the leading zero. Always use <code>StringType</code> for identifiers that happen to look like numbers.</li>
<li><strong>Ignoring <code>nullable</code>.</strong> If you mark a column as <code>nullable=False</code> but your data has nulls, Spark won't throw an error by default — it'll silently allow them. The <code>nullable</code> flag is metadata for the optimizer, not strict enforcement. Use <code>.filter(col("name").isNotNull())</code> if you need to guarantee no nulls.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Explicit schemas skip the double-read that <code>inferSchema</code> requires — up to 2-3x faster on large files.</li>
<li>Use <code>StructType</code> + <code>StructField</code> for production code, DDL strings for quick exploration.</li>
<li>Choose data types intentionally: <code>StringType</code> for identifiers, <code>LongType</code> for big numbers, <code>DecimalType</code> for money.</li>
<li>Use <code>mode="FAILFAST"</code> during development to catch schema mismatches early.</li>
<li>The <code>nullable</code> flag is advisory, not enforced — validate your data explicitly.</li>
</ul>
