</div><h2 id="the-core-difference">The Core Difference</h2>
<p><strong>Pandas</strong> runs on a single machine and stores data in memory. It's fast, intuitive, and perfect for exploratory data analysis.</p>
<p><strong>Spark</strong> distributes data across a cluster of machines. It handles massive datasets but has more overhead for small tasks.</p>
<p>Think of it this way: Pandas is a sports car (fast, nimble, limited cargo). Spark is a freight train (slower to start, but moves mountains of data).</p>

<h2 id="lazy-vs-eager-evaluation">Lazy vs Eager Evaluation</h2>
<p>This is the biggest conceptual difference. Pandas executes operations immediately:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Pandas: this runs RIGHT NOW</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">filtered </span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2">=</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> df[df[</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"revenue"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">] </span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2">></span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> 30</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">]</span></span></code></pre>
<p>Spark builds a plan but doesn't execute it until you ask for results:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># PySpark: this just creates a plan</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">filtered </span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2">=</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> df.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">filter</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(df[</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"revenue"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">] </span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2">></span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> 30</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)</span></span>

<p>This lazy approach lets Spark optimize the entire pipeline before running it — like a GPS planning the fastest route before you start driving.</p>
<h2 id="when-to-use-each">When to Use Each</h2>
<h3 id="use-pandas-when">Use Pandas when:</h3>
<ul>
<li>Your data fits in memory (&#x3C; 10GB)</li>
<li>You're doing exploratory data analysis</li>
<li>You need quick, interactive results</li>
<li>You're prototyping before building a pipeline</li>
</ul>
<h3 id="use-spark-when">Use Spark when:</h3>
<ul>
<li>Your data exceeds a single machine's memory</li>
<li>You need to process data on a schedule (ETL)</li>
<li>You're joining multiple large datasets</li>
<li>You need real-time streaming capabilities</li>
</ul>
<h2 id="the-migration-path">The Migration Path</h2>
<p>Many teams start with Pandas for prototyping, then migrate to Spark for production. PySpark's DataFrame API is intentionally similar to Pandas to make this transition smoother.</p>

<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Using Spark for a 100MB file.</strong> Spark's startup time alone might be longer than Pandas processing the whole file. Use the right tool for the scale.</li>
<li><strong>Collecting all Spark data to the driver.</strong> <code>df.collect()</code> pulls all data to a single machine — defeating the purpose. Use <code>.show()</code> or <code>.take(n)</code> instead.</li>
<li><strong>Assuming identical APIs.</strong> While similar, there are differences. For example, Pandas uses <code>df['col']</code> for selection, PySpark uses <code>df.select('col')</code>.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Pandas is best for datasets under ~10GB on a single machine</li>
<li>Spark is best for large-scale distributed data processing</li>
<li>Spark uses lazy evaluation, Pandas uses eager evaluation</li>
<li>The APIs are similar by design to ease migration</li>
<li>Start with Pandas, move to Spark when data outgrows it</li>
</ul>
