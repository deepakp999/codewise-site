<h3 id="createorreplace-vs-create">createOrReplace vs create</h3>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># createOrReplaceTempView — overwrites if the view already exists</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">df.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">createOrReplaceTempView</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"employees"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Safe to call multiple times</span></span>

<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># createTempView — throws an error if the view already exists</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">df.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">createTempView</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"new_view"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Fails if "new_view" already exists</span></span></code></pre>
<p>Use <code>createOrReplaceTempView</code> almost always — it's safer because you don't have to worry about whether the view already exists.</p>
<h2 id="global-temp-views-rarely-needed">Global Temp Views (Rarely Needed)</h2>
<p>A global temp view is visible across different SparkSessions within the same Spark application. It lives in a special <code>global_temp</code> database.</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Query a global temp view — must prefix with global_temp.</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">spark.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">sql</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"SELECT * FROM global_temp.employees_global"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">).</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">show</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">()</span></span></code></pre>
<div data-cw-section="output-block"><h3 id="expected-output-1">Expected Output</h3>
<pre data-cw-output="true"><code>+-------+------+
|   name|salary|
+-------+------+
|  Alice|120000|
|    Bob| 95000|
|Charlie|130000|
+-------+------+
</code></pre></div>
<p>Note the <code>global_temp.</code> prefix — this is required. Without it, Spark looks for a regular temp view and won't find it.</p>
<p><strong>When would you use this?</strong> Almost never in practice. Global temp views matter when you have multiple SparkSessions in the same application (rare) or when different notebooks in the same Spark cluster need to share data. For single-session scripts and pipelines, regular temp views are all you need.</p>

<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">    WHERE total_revenue > 10000</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">    ORDER BY order_date</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"""</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">).</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">show</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">()</span></span></code></pre>
<p>Each view builds on the previous one — <code>raw_orders</code> → <code>clean_orders</code> → <code>daily_summary</code>. This is readable and each intermediate step is queryable for debugging.</p>
<h2 id="views-vs-dataframes--whats-the-difference">Views vs DataFrames — What's the Difference?</h2>
<p>A view IS a DataFrame with a SQL name attached. Under the hood, they're the same thing:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># These are equivalent</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">df.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">filter</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">col</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"salary"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">) </span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2">></span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> 100000</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">).</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">show</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">()</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">spark.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">sql</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"SELECT * FROM employees WHERE salary > 100000"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">).</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">show</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">()</span></span></code></pre>
<p>The only difference is how you access them:</p>
<ul>
<li><strong>DataFrame variable</strong> (<code>df</code>) — used in Python code</li>
<li><strong>View name</strong> (<code>"employees"</code>) — used in SQL strings</li>
</ul>
<p>Both point to the same data. Both use the same optimizer. Neither copies the data.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Forgetting the <code>global_temp.</code> prefix for global views.</strong> <code>SELECT * FROM employees_global</code> fails. You need <code>SELECT * FROM global_temp.employees_global</code>. This is the #1 confusion with global views.</li>
<li><strong>Expecting views to survive a session restart.</strong> If your Spark application restarts, all temp views are gone. If you need persistent tables, you need a metastore (Hive) — that's beyond our scope but worth knowing exists.</li>
<li><strong>Creating too many views in a complex pipeline.</strong> Views are free (no data copying), but too many make debugging harder. Use views for logical stages in your pipeline — raw, cleaned, aggregated — not for every minor transformation.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li><code>createOrReplaceTempView</code> is your go-to — use it for all SQL access to DataFrames.</li>
<li>Temp views live in the current SparkSession only. Global temp views live across sessions but require the <code>global_temp.</code> prefix.</li>
<li>Views don't copy data — they're just SQL-accessible names for existing DataFrames.</li>
<li>Use views to create readable pipeline stages: raw → cleaned → aggregated → output.</li>
<li>Always use <code>createOrReplaceTempView</code> over <code>createTempView</code> to avoid "view already exists" errors.</li>
</ul>
