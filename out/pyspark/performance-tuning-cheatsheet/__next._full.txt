19:T7a81,<h1 id="pyspark-performance-tuning-cheat-sheet">PySpark Performance Tuning Cheat Sheet</h1>
<h2 id="what-this-page-is">What This Page Is</h2>
<p>This is a one-page reference — not a lesson. Bookmark it. Come back to it when your PySpark job is slow. Every tip here is explained in detail in earlier lessons (referenced in parentheses).</p>
<h2 id="rule-1-reduce-what-gets-shuffled">Rule 1: Reduce What Gets Shuffled</h2>
<p>Shuffles are the #1 performance bottleneck. (Lesson 20)</p>
<p><strong>Filter early.</strong> Move <code>filter()</code> before <code>groupBy()</code> and <code>join()</code>. Fewer rows = smaller shuffle.</p>
<p><strong>Select only needed columns.</strong> Before a join, select only the join key plus the columns you actually need. <code>orders.select("customer_id", "amount").join(...)</code> shuffles less data than <code>orders.join(...)</code>.</p>
<p><strong>Use <code>agg()</code> for multiple aggregations.</strong> <code>df.groupBy("dept").agg(count("*"), avg("salary"))</code> shuffles once. Separate <code>count()</code> and <code>avg()</code> calls shuffle twice.</p>
<p><strong>Avoid unnecessary <code>orderBy()</code>.</strong> Sorting triggers a full shuffle. Only sort at the final output step if the consumer requires ordered data.</p>
<h2 id="rule-2-broadcast-small-tables">Rule 2: Broadcast Small Tables</h2>
<p>If one join table fits in executor memory (&#x3C; 100 MB), broadcast it. (Lesson 25)</p>

<p>Spark auto-broadcasts tables under 10 MB. Override with:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">spark.conf.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">set</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"spark.sql.autoBroadcastJoinThreshold"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">, </span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">50</span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2"> *</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> 1024</span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2"> *</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> 1024</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># 50 MB</span></span></code></pre>
<p>Check <code>explain()</code> for <code>BroadcastHashJoin</code> to verify.</p>

<ul>

<li>Executors sitting idle → too few partitions</li>
</ul>
<h2 id="rule-4-cache-wisely">Rule 4: Cache Wisely</h2>
<p>Cache DataFrames that are expensive AND reused. (Lesson 24)</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">expensive_df.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">cache</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">()          </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Mark for caching</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">expensive_df.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">count</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">()          </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Force materialization</span></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># ... use expensive_df multiple times ...</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">expensive_df.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">unpersist</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">()      </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Free memory when done</span></span></code></pre>
<p><strong>Do cache:</strong> Join results used for multiple output tables. Filtered datasets used in multiple aggregations.</p>
<p><strong>Don't cache:</strong> DataFrames used only once. Cheap operations (simple selects). Very large DataFrames that won't fit in memory.</p>

<h2 id="rule-6-use-the-right-file-format">Rule 6: Use the Right File Format</h2>

<h2 id="debugging-checklist">Debugging Checklist</h2>
<p>When a PySpark job is slow:</p>
<ol>
<li><strong>Open the Spark UI</strong> (localhost:4040)</li>
<li><strong>Check stages</strong> — which stage is slowest?</li>
<li><strong>Check shuffle size</strong> — is it disproportionately large?</li>
<li><strong>Check task distribution</strong> — is one task much slower (skew)?</li>
<li><strong>Run <code>explain()</code></strong> — is Spark doing BroadcastHashJoin or SortMergeJoin?</li>
<li><strong>Check partition count</strong> — too many small tasks or too few large ones?</li>
<li><strong>Check for UDFs</strong> — can they be replaced with built-in functions?</li>
<li><strong>Check caching</strong> — are expensive DataFrames recomputed multiple times?</li>
</ol>
