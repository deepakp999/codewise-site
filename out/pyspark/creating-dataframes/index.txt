19:T71e9,<h1 id="creating-dataframes-from-lists-dicts-and-files">Creating DataFrames from Lists, Dicts, and Files</h1>
<div data-cw-section="learn-box"><h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>Five different ways to create a PySpark DataFrame</li>
<li>When to use each approach</li>
<li>How to create DataFrames from CSV, JSON, and Parquet files</li>

</div><h2 id="why-this-matters">Why This Matters</h2>
<p>In Lesson 4, we created a simple DataFrame from a list of tuples. That's fine for learning, but in real data engineering, your data comes from files — CSVs exported from databases, JSON from APIs, Parquet files in data lakes. Knowing all the ways to get data into PySpark is the foundation for everything else.</p>

<p>Notice there's no <code>header=True</code> or <code>inferSchema=True</code> — Parquet files carry their own schema. This is one reason data engineers prefer Parquet over CSV.</p>
<h2 id="inferschema-convenient-but-costly">inferSchema: Convenient but Costly</h2>
<p>When you use <code>inferSchema=True</code> on a CSV, Spark has to read the entire file once just to figure out the data types, then read it again to actually process it. On a 100 GB CSV, that's two full passes.</p>
<p>In production, you should provide an explicit schema instead. We'll cover this in the next lesson.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Forgetting <code>header=True</code> when reading CSV.</strong> Without it, Spark treats the first row as data, not column names. Your columns will be named <code>_c0</code>, <code>_c1</code>, <code>_c2</code> and your header row will appear as data.</li>
<li><strong>Using <code>inferSchema=True</code> on large files in production.</strong> It doubles the read time. Define your schema explicitly instead — we'll show you how in Lesson 7.</li>
<li><strong>Assuming JSON means a JSON array.</strong> PySpark expects JSON Lines format (one object per line) by default. A file with <code>[{...}, {...}]</code> will fail unless you set <code>multiLine=true</code>.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Use lists/tuples for quick testing, pandas conversion for prototyping, and file reads for real work.</li>
<li>CSV needs <code>header=True</code> to use the first row as column names.</li>
<li><code>inferSchema=True</code> is convenient but slow on large files — provide an explicit schema in production.</li>
<li>Parquet is self-describing — no schema options needed.</li>
<li>JSON Lines (one object per line) is the default JSON format for PySpark.</li>
</ul>
