</div><h2 id="why-this-matters">Why This Matters</h2>
<p>In Lesson 4, we created a simple DataFrame from a list of tuples. Knowing all the ways to get data into PySpark is the foundation for everything else.</p>

<p>Let's break down the options:</p>
<ul>
<li><code>header=True</code> — the first row contains column names (not data)</li>
<li><code>inferSchema=True</code> — Spark reads through the data to guess column types</li>
</ul>
<p>You can also use the more verbose format:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">df </span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2">=</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> spark.read \</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    .</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">format</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"csv"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">) \</span></span>

<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    .</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">option</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"inferSchema"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">, </span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"true"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">) \</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    .</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">option</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"sep"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">, </span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">","</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">) \</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    .</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">load</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"employees.csv"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)</span></span></code></pre>
<h2 id="way-5-from-json-files">Way 5: From JSON Files</h2>
<p>JSON is common when working with API data:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Read a JSON file (one JSON object per line)</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">df </span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2">=</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> spark.read.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">json</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"orders.json"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)</span></span>

<h2 id="bonus-from-parquet-files">Bonus: From Parquet Files</h2>
<p>Parquet is the format data engineers use in production. It's columnar, compressed, and fast. We'll cover why in Lesson 12, but here's how to read it:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic"># Read Parquet — no options needed, schema is embedded in the file</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">df </span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2">=</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> spark.read.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">parquet</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"data/sales.parquet"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">df.</span><span style="--shiki-light:#24292E;--shiki-dark:#61AFEF">show</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">3</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)</span></span></code></pre>
<p>Notice there's no <code>header=True</code> or <code>inferSchema=True</code> — Parquet files carry their own schema. This is one reason data engineers prefer Parquet over CSV.</p>
<h2 id="inferschema-convenient-but-costly">inferSchema: Convenient but Costly</h2>
<p>When you use <code>inferSchema=True</code> on a CSV, Spark has to read the entire file once just to figure out the data types, then read it again to actually process it. On a 100 GB CSV, that's two full passes.</p>
<p>In production, you should provide an explicit schema instead. We'll cover this in the next lesson.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Forgetting <code>header=True</code> when reading CSV.</strong> Without it, Spark treats the first row as data, not column names. Your columns will be named <code>_c0</code>, <code>_c1</code>, <code>_c2</code> and your header row will appear as data.</li>
<li><strong>Using <code>inferSchema=True</code> on large files in production.</strong> It doubles the read time. Define your schema explicitly instead — we'll show you how in Lesson 7.</li>
<li><strong>Assuming JSON means a JSON array.</strong> PySpark expects JSON Lines format (one object per line) by default. A file with <code>[{...}, {...}]</code> will fail unless you set <code>multiLine=true</code>.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Use lists/tuples for quick testing, pandas conversion for prototyping, and file reads for real work.</li>
<li>CSV needs <code>header=True</code> to use the first row as column names.</li>
<li><code>inferSchema=True</code> is convenient but slow on large files — provide an explicit schema in production.</li>
<li>Parquet is self-describing — no schema options needed.</li>
<li>JSON Lines (one object per line) is the default JSON format for PySpark.</li>
</ul>
