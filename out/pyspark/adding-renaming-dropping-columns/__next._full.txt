<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Chaining many <code>withColumn</code> calls for unrelated columns.</strong> Each <code>withColumn</code> creates a new DataFrame object. While Spark optimizes this internally, using <code>select</code> with multiple expressions is often cleaner and can be more performant for many columns at once.</li>
<li><strong>Forgetting <code>lit()</code> for constant values.</strong> <code>df.withColumn("status", "active")</code> will throw an error. You need <code>df.withColumn("status", lit("active"))</code> because the second argument must be a column expression.</li>
<li><strong>Not ending <code>when</code> chains with <code>otherwise()</code>.</strong> If no condition matches and there's no <code>otherwise</code>, the value is <code>null</code>. This is often a silent bug — your data looks correct until you realize some rows have unexplained nulls.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li><code>withColumn</code> adds or replaces a column — the original DataFrame stays unchanged.</li>
<li>Use <code>lit()</code> for constant values, <code>when/otherwise</code> for conditional logic.</li>
<li><code>withColumnRenamed</code> renames one column at a time; <code>toDF</code> renames all at once by position.</li>
<li><code>drop()</code> silently ignores columns that don't exist.</li>
<li>Chain transformations for readable, pipeline-style code.</li>
</ul>
