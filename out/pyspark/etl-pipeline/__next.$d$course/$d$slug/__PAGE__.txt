<div data-cw-section="learn-box"><h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>How to structure an ETL pipeline in PySpark</li>
<li>How to read from multiple sources and join them</li>

<li>How to write clean, partitioned output</li>
<li>A complete, runnable pipeline you can adapt for your own projects</li>
</ul>
</div><h2 id="what-is-etl">What Is ETL?</h2>
<p>ETL stands for Extract, Transform, Load — the three steps of every data pipeline:</p>
<ol>
<li><strong>Extract</strong> — read raw data from source systems (CSV, JSON, databases, APIs)</li>
<li><strong>Transform</strong> — clean, join, aggregate, and reshape the data</li>
<li><strong>Load</strong> — write the results to a destination (data warehouse, data lake, dashboard)</li>
</ol>
<p>This is the core of what data engineers do every day. Let's build one.</p>
<h2 id="the-scenario">The Scenario</h2>
<p>You're a data engineer at an e-commerce company. Every day, you receive three data files:</p>
<ul>
<li><code>orders.csv</code> — every order placed</li>
<li><code>products.json</code> — product catalog</li>
<li><code>customers.csv</code> — customer directory</li>
</ul>
<p>Your job: build a daily pipeline that produces a clean, enriched <code>order_details</code> table with customer names, product info, and revenue metrics, partitioned by date.</p>

<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Not validating input data before transforming.</strong> Always check row counts and null counts after reading. If <code>orders.count()</code> returns 0, you want to fail fast — not silently produce empty output tables.</li>
<li><strong>Using <code>mode("overwrite")</code> without understanding what it overwrites.</strong> Overwrite replaces the entire output directory. If your pipeline fails halfway through writing, you've lost the previous data AND don't have complete new data. Consider writing to a temp directory first, then renaming.</li>
<li><strong>Joining without thinking about data size.</strong> If products has 1000 rows and orders has 10 million, broadcast the products table (Lesson 25) instead of doing a full shuffle join.</li>
<li><strong>Not partitioning output by commonly queried columns.</strong> If downstream queries always filter by date, partition by year/month so those queries skip irrelevant files.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>ETL pipelines follow a clear structure: Extract (read sources) → Transform (clean, join, aggregate) → Load (write output).</li>
<li>Always define schemas explicitly for production pipelines.</li>
<li>Clean data early — filter nulls and bad values before joins and aggregations.</li>
<li>Partition output by columns that downstream queries filter on.</li>
<li>Wrap pipelines in functions for testability and reuse.</li>
<li>Validate input data and use defensive coding practices.</li>
</ul>
