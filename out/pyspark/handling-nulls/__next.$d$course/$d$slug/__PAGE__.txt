<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Using <code>== None</code> instead of <code>.isNull()</code>.</strong> In PySpark, <code>col("salary") == None</code> does NOT work. Use <code>col("salary").isNull()</code> or <code>col("salary").isNotNull()</code>. This is different from Python where <code>x is None</code> works.</li>
<li><strong>Filling nulls with the wrong type.</strong> <code>df.fillna("0", subset=["salary"])</code> fills a numeric column with the string "0" only if the column is a string type. For integer columns, use <code>df.fillna(0, subset=["salary"])</code> — the value must match the column's data type.</li>
<li><strong>Dropping nulls too aggressively.</strong> Using <code>dropna()</code> without <code>subset</code> or <code>thresh</code> can remove most of your data. Always check how many rows you'll lose first: <code>df.dropna().count()</code> vs <code>df.count()</code>.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Always start by counting nulls per column to understand the scope of the problem.</li>
<li><code>dropna(subset=[...])</code> is safer than <code>dropna()</code> — only drop rows where critical columns are null.</li>
<li><code>fillna()</code> with a dictionary lets you set different defaults for different columns.</li>
<li><code>coalesce()</code> is powerful for "fall through" logic — use the first available value from multiple sources.</li>
<li>Clean strings with <code>trim()</code> and <code>lower()</code> before doing any comparisons or groupBy operations.</li>
<li>Use <code>.isNull()</code> and <code>.isNotNull()</code> — never <code>== None</code>.</li>
</ul>
