1b:T4ba9,<h1 id="annotations--ui-search-odata-and-metadata-extensions">Annotations — UI, Search, OData, and Metadata Extensions</h1>
<div data-cw-section="learn-box"><h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>What annotations are and why they're unique to CDS</li>
<li>@UI annotations for Fiori Elements layout</li>

<li>@OData annotations for service behavior</li>
<li>Metadata extensions — separating UI concerns from data models</li>
</ul>
</div><h2 id="what-are-annotations">What Are Annotations?</h2>
<p>Annotations are metadata that you attach to CDS views and fields. They don't change the data — they tell consumers (Fiori, OData, analytics) <strong>how</strong> to use the data.</p>
<p>Think of annotations like labels on a shipping box. The box content (data) doesn't change, but the labels tell the handler: "Fragile" (display as read-only), "This Side Up" (show in this position on the UI), "Express" (searchable, high priority).</p>
<p>In Classic ABAP, you'd control UI layout in dynpro screen painter or ALV field catalog. In modern ABAP, annotations do this declaratively — no code needed.</p>

<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">      category </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">AS</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> Category,</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">      </span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">      product_id </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">AS</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ProductId</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">}</span></span></code></pre>
<p>This enables fuzzy search in Fiori apps. A user typing "widgt" in the search bar will find "Widget Pro" because the fuzziness threshold allows approximate matches.</p>
<h2 id="metadata-extensions--keep-views-clean">Metadata Extensions — Keep Views Clean</h2>
<p>Putting dozens of UI annotations directly in a CDS view makes it hard to read. <strong>Metadata extensions</strong> separate UI concerns from data modeling:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">" Step 1: The CDS view stays clean — data only</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">@AccessControl.authorizationCheck: #NOT_REQUIRED</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">@EndUserText.label: 'TechMart Product'</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">@Metadata.allowExtensions: true   -- THIS enables metadata extensions</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">DEFINE VIEW ENTITY ZI_TM_Product</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  AS SELECT FROM ztm_product</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">{</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  key product_id     AS ProductId,</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">      name           AS ProductName,</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">      category       AS Category,</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">      price          AS Price,</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">      currency       AS Currency,</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">      stock_quantity AS StockQuantity</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">}</span></span></code></pre>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">" Step 2: A separate metadata extension handles UI annotations</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">@Metadata.layer: #CORE</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">ANNOTATE VIEW ENTITY ZI_TM_Product WITH</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">{</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  @UI.facet: [{ id: 'ProductInfo',</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">                type: #IDENTIFICATION_REFERENCE,</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">                label: 'Product Details',</span></span>

<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">         identification: [{ position: 10 }],</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">         selectionField: [{ position: 10 }] }</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  ProductId;</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  </span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  @UI: { lineItem:       [{ position: 20, importance: #HIGH }],</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">         identification: [{ position: 20 }] }</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  ProductName;</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  </span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  @UI: { lineItem:       [{ position: 30 }],</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">         selectionField: [{ position: 20 }] }</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  Category;</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  </span></span>

<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">         identification: [{ position: 40 }] }</span></span>

<p><strong>Best practice:</strong> Always use metadata extensions for UI annotations. Keep the CDS view entity focused on data modeling. This separation is a Clean Core principle.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Embedding UI annotations directly in interface views</strong> — Use metadata extensions instead. Interface views (<code>ZI_</code>) should be pure data models.</li>
<li><strong>Forgetting <code>@Metadata.allowExtensions: true</code></strong> — Without this, you can't create metadata extensions for the view.</li>
<li><strong>Wrong position numbering</strong> — Use increments of 10 (10, 20, 30) so you can insert fields later without renumbering.</li>
<li><strong>Overannotating</strong> — Not every field needs to be on every UI facet. Show only what users need.</li>
<li><strong>Ignoring <code>importance</code></strong> — On mobile devices, only <code>#HIGH</code> importance fields show. If your key fields are <code>#LOW</code>, mobile users see an empty list.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Annotations are metadata that control how CDS data is consumed — by Fiori, OData, analytics, and search.</li>
<li>@UI annotations generate complete Fiori Elements UIs without frontend code. <code>lineItem</code> = list columns, <code>identification</code> = detail page, <code>selectionField</code> = search filters.</li>
<li>@Search annotations enable fuzzy full-text search in Fiori apps.</li>
<li>Metadata extensions separate UI concerns from data models — always use them for UI annotations.</li>
<li>Annotations are declarative — you describe WHAT you want, not HOW to build it.</li>
</ul>
