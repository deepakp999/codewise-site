1b:T15f9,<h1 id="service-definition-and-service-binding">Service Definition and Service Binding</h1>
<div data-cw-section="learn-box"><h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>What service definitions and service bindings are</li>
<li>Creating an OData V4 service for TechMart's Sales Order</li>
<li>Testing with Fiori Elements preview</li>
<li>The difference between OData V2 and V4</li>
<li>How annotations drive the generated UI</li>
</ul>
</div><h2 id="service-definition--what-to-expose">Service Definition — What to Expose</h2>
<p>The service definition lists which entities from your projection are available via OData:</p>
<p>In ADT: Right-click package → <strong>New → Service Definition</strong></p>
<pre><code>@EndUserText.label: 'TechMart Sales Order Service'
define service ZSD_TM_SALESORDER {
  expose ZC_TM_SalesOrder as SalesOrder;
  expose ZC_TM_SalesOrderItem as SalesOrderItem;
  expose ZI_TM_Customer as Customer;
  expose ZI_TM_Product as Product;
}
</code></pre>
<p>You expose projection views (for transactional entities) and interface views (for reference data like Customer and Product). The <code>as</code> alias becomes the entity set name in OData.</p>
<h2 id="service-binding--how-to-expose">Service Binding — How to Expose</h2>
<p>The service binding connects the definition to a protocol:</p>
<p>In ADT: Right-click package → <strong>New → Service Binding</strong></p>
<ul>
<li>Name: <code>ZSB_TM_SALESORDER_V4</code></li>
<li>Binding Type: <strong>OData V4 - UI</strong></li>
<li>Service Definition: <code>ZSD_TM_SALESORDER</code></li>
</ul>
<p>After activation, click <strong>Publish</strong> in the service binding editor. This registers the OData service.</p>
<p>Then click <strong>Preview</strong> next to the <code>SalesOrder</code> entity set. ADT launches a browser with a fully functional Fiori Elements list report + object page — generated entirely from your CDS annotations.</p>
<div data-cw-section="output-block"><h3 id="expected-output-fiori-preview">Expected Output (Fiori Preview)</h3>
<pre data-cw-output="true"><code>┌─────────────────────────────────────────────────────┐

<p>You can create, edit, and delete orders right from this preview. No frontend code written.</p>

<p><strong>Default to OData V4</strong> for all new development.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Exposing interface views for transactional entities</strong> — Expose projection views (<code>ZC_</code>) for entities with CRUD. Interface views (<code>ZI_</code>) can be exposed for read-only reference data.</li>
<li><strong>Forgetting to Publish</strong> — Activating the service binding is not enough. You must click <strong>Publish</strong> to register the OData service.</li>
<li><strong>Missing UI annotations</strong> — The Fiori preview generates UI from annotations. If your fields have no <code>@UI.lineItem</code>, the list is empty.</li>
<li><strong>Wrong binding type</strong> — Use "OData V4 - UI" for Fiori apps. "OData V4 - Web API" is for programmatic consumption without UI.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Service definition lists WHICH entities to expose. Service binding defines HOW (OData V2/V4).</li>
<li>Fiori Elements preview generates a complete UI from CDS annotations — no frontend code.</li>
<li>Default to OData V4 for new apps.</li>
<li>Publish the service binding after activation.</li>
<li>The Fiori preview is your primary testing tool during RAP development.</li>
</ul>
