1b:T4ba0,<h1 id="the-abap-cloud-development-model">The ABAP Cloud Development Model</h1>
<div data-cw-section="learn-box"><h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>What the ABAP Cloud development model is and where it applies</li>
<li>What "released APIs" are and why they matter</li>
<li>How the ABAP Test Cockpit (ATC) enforces the rules</li>
<li>The clean core extensibility levels (A through D)</li>
<li>What you CAN and CAN'T do in ABAP Cloud</li>
</ul>
</div><h2 id="the-rulebook">The Rulebook</h2>
<p>In Classic ABAP, you could do almost anything. Access any SAP table. Call any function module. Modify standard includes. It worked, but it created a maintenance nightmare — every SAP upgrade could break your custom code.</p>
<p>ABAP Cloud is the opposite approach: <strong>you can only use what SAP explicitly allows.</strong></p>
<p>Think of it as the difference between a wild-west town and a gated community. In the wild west (Classic ABAP), you build wherever you want, however you want. In the gated community (ABAP Cloud), there are building codes, approved contractors, and a homeowners' association (the ABAP Test Cockpit) that checks everything.</p>
<h2 id="where-does-abap-cloud-apply">Where Does ABAP Cloud Apply?</h2>
<p>ABAP Cloud is mandatory in:</p>
<ul>
<li><strong>SAP BTP ABAP Environment</strong> — the cloud-only ABAP runtime</li>
<li><strong>S/4HANA Cloud Public Edition</strong> — SAP's SaaS offering</li>
</ul>
<p>ABAP Cloud is optional (but recommended) in:</p>
<ul>
<li><strong>S/4HANA Cloud Private Edition</strong> — hosted cloud, customer-managed</li>
<li><strong>S/4HANA On-Premise</strong> — traditional installation</li>
</ul>
<p>TechMart is migrating to S/4HANA Cloud, so ABAP Cloud is mandatory for us. But even if your company is on-premise, learning ABAP Cloud now means your code is future-proof.</p>
<h2 id="released-apis--the-core-concept">Released APIs — The Core Concept</h2>
<p>In Classic ABAP, if you needed customer data, you might write:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Classic approach — WORKS, but NOT cloud-safe</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">SELECT</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> *</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> FROM</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> kna1 </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">INTO TABLE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> @</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DATA</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">lt_customers</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  WHERE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> land1 </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">=</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'US'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span></code></pre>
<p>This accesses <code>KNA1</code> directly — an SAP internal table. If SAP restructures this table in a future release, your code breaks.</p>
<p>In ABAP Cloud, you use a <strong>released API</strong> instead:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" ABAP Cloud approach — uses a released CDS view</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">SELECT</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> *</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> FROM</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> I_Customer </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">INTO TABLE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> @</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DATA</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">lt_customers</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  WHERE</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> Country</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> =</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'US'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span></code></pre>
<p><code>I_Customer</code> is a CDS view released by SAP. SAP guarantees its interface stability. Even if SAP restructures the underlying tables, <code>I_Customer</code> continues to work.</p>
<p><strong>How to know if something is released:</strong> In ADT, every SAP object has an "API State" property. If it says <code>Released</code> with a stability contract (C1 = use in cloud, C2 = use in key user extensibility), it's safe to use. If it doesn't, it's off-limits in ABAP Cloud.</p>
<div data-cw-section="output-block"><h3 id="expected-output-api-state-in-adt">Expected Output (API State in ADT)</h3>
<p>When you open a released CDS view in ADT, you'll see:</p>
<pre data-cw-output="true"><code>Properties:
  API State: Released
  Stability Contract: C1 (Use in Cloud Development)
  Visibility: Public
  Release State: Released
</code></pre></div>
<p>If you try to use an unreleased object, the ATC flags it immediately.</p>
<h2 id="the-abap-test-cockpit-atc--your-gatekeeper">The ABAP Test Cockpit (ATC) — Your Gatekeeper</h2>
<p>The ATC is a static code analysis tool. In ABAP Cloud, it runs automatically and <strong>blocks transport</strong> if your code violates the rules.</p>
<p>Key checks the ATC performs:</p>
<ul>
<li><strong>Released API check</strong> — Did you use only released objects?</li>
<li><strong>Obsolete syntax check</strong> — Did you use deprecated statements?</li>
<li><strong>Clean ABAP check</strong> — Does your code follow naming conventions and best practices?</li>
</ul>

<h2 id="clean-core-extensibility-levels">Clean Core Extensibility Levels</h2>
<p>SAP introduced a graduated model for classifying custom code. This helps companies plan their migration:</p>
<p><strong>Level A — Fully Cloud-Ready</strong></p>
<ul>
<li>Uses only released APIs (C1 contract)</li>
<li>Built with ABAP Cloud, CDS, and RAP</li>
<li>Upgrade-safe, no risk during quarterly updates</li>
<li><em>This is what we build in this course</em></li>
</ul>
<p><strong>Level B — Stable Classic</strong></p>
<ul>
<li>Uses documented, generally stable SAP APIs</li>
<li>Not officially released, but unlikely to break</li>
<li>Acceptable with governance sign-off</li>
<li>Requires monitoring during upgrades</li>
</ul>
<p><strong>Level C — Risky Classic</strong></p>
<ul>
<li>Accesses SAP internal objects</li>
<li>Meaningful upgrade risk</li>
<li>Should be on a remediation roadmap</li>
</ul>
<p><strong>Level D — Dangerous</strong></p>
<ul>
<li>Modifications to SAP standard code</li>
<li>Implicit enhancements, direct writes to SAP tables</li>
<li>Severe upgrade risk</li>
<li>Should have a retirement timeline</li>
</ul>
<p>TechMart's goal: all new development at Level A, existing code assessed and migrated from C/D → A/B over time.</p>

<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>"Released APIs don't cover my use case"</strong> — This is sometimes true in early adoption. SAP releases new APIs with each quarterly update. Check the SAP API Business Hub for the latest. If your API truly doesn't exist, Level B (stable classic) is acceptable with governance sign-off.</li>
<li><strong>"ATC is just a recommendation I can ignore"</strong> — In ABAP Cloud, ATC violations block transport. You literally cannot deploy non-compliant code. On-premise, it's configurable — but treat it as mandatory.</li>
<li><strong>"I'll learn clean core later"</strong> — Every line of non-compliant code you write today is technical debt tomorrow. Start clean, stay clean.</li>
<li><strong>Confusing ABAP Cloud with SAP BTP</strong> — ABAP Cloud is a development model (a set of rules). SAP BTP is a platform. You can use ABAP Cloud on BTP, on S/4HANA Cloud, and on S/4HANA on-premise. They're different things.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>ABAP Cloud restricts you to released APIs — SAP's guarantee of upgrade stability.</li>
<li>The ABAP Test Cockpit (ATC) enforces these rules automatically and blocks non-compliant code from transport.</li>
<li>Clean Core extensibility ranges from Level A (fully cloud-ready) to Level D (dangerous modifications). Aim for Level A.</li>
<li>You lose classic tools (SE80, function modules, dynpros) but gain a safer, more productive development model.</li>
<li>This course builds everything at Level A — fully cloud-ready, fully upgrade-safe.</li>
</ul>
