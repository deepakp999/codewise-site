</div><h2 id="why-calculated-fields">Why Calculated Fields?</h2>
<p>Raw database data rarely matches business needs. TechMart stores order status as a single character (<code>N</code>, <code>P</code>, <code>C</code>, <code>X</code>), but users want to see "New", "In Process", "Completed", "Cancelled". Classic ABAP handled this in the application layer. In CDS, you handle it in the view — on the database.</p>

<p>Common types in CDS CAST:</p>
<ul>
<li><code>abap.char(n)</code> — character string</li>
<li><code>abap.int4</code> — 4-byte integer</li>
<li><code>abap.dec(p,s)</code> — packed decimal</li>
<li><code>abap.curr(p,s)</code> — currency amount</li>
<li><code>abap.dats</code> — date (YYYYMMDD)</li>
<li><code>abap.string</code> — variable-length string</li>
</ul>

<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>CAST to wrong type</strong> — <code>CAST(amount AS abap.char(10))</code> will truncate decimals. Use the appropriate type for the data.</li>
<li><strong>Division by zero</strong> — <code>DIVISION(a, b, 2)</code> handles zero safely, but plain <code>a / b</code> crashes. Always use <code>DIVISION()</code> or add a CASE check.</li>
<li><strong>CASE without ELSE</strong> — If no WHEN matches and there's no ELSE, the result is NULL. Always include ELSE.</li>
<li><strong>Mixing aggregated and non-aggregated fields</strong> — If you use COUNT/SUM/AVG, every non-aggregated field must be in GROUP BY.</li>
<li><strong>Calculated field performance</strong> — Complex calculations in CDS push to the database, which is good. But string manipulation on millions of rows can still be slow. Keep calculations targeted.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>CDS calculated fields transform data on the database — no ABAP processing needed.</li>
<li>CASE expressions replace IF-ELSE logic for field derivation.</li>
<li>CAST is mandatory when mixing types or exposing data through OData.</li>
<li>SQL functions (CONCAT, SUBSTRING, DATS_DAYS_BETWEEN, DIVISION) handle common transformations.</li>
<li>Aggregation views with GROUP BY replace Classic ABAP COLLECT patterns.</li>
</ul>
