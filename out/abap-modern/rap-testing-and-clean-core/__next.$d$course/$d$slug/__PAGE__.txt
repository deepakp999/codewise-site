</div><h2 id="why-test-rap">Why Test RAP?</h2>
<p>In Classic ABAP, testing was often manual — run the transaction, enter data, check the output. That worked when systems were simple. TechMart's Sales Order BO has validations, determinations, actions, draft, and feature control. Manual testing every combination after every change would take days.</p>
<p>ABAP Unit tests run in seconds, catch regressions immediately, and document expected behavior.</p>

<h2 id="running-atc-for-clean-core">Running ATC for Clean Core</h2>
<p>The ABAP Test Cockpit validates your code is cloud-ready:</p>
<ol>
<li>In ADT: Right-click your package → <strong>Run As → ABAP Test Cockpit With...</strong></li>
<li>Select check variant: <strong>ABAP_CLOUD_DEVELOPMENT</strong></li>
<li>Review findings</li>
</ol>
<p>ATC checks for:</p>
<ul>
<li>Use of unreleased APIs</li>
<li>Obsolete syntax</li>
<li>Missing exception handling</li>
<li>Clean ABAP style violations</li>
</ul>
<p><strong>Target: zero Priority 1 and 2 findings.</strong> Priority 3 findings are warnings — fix them when practical.</p>
<pre><code>ATC Results:
  ✓ zbp_i_tm_salesorder      — No findings
  ✓ ZI_TM_SalesOrder         — No findings
  ⚠ zcl_tm_product_analytics — P3: Consider using FINAL() instead of DATA()
  ✗ zcl_tm_legacy_helper     — P1: Use of unreleased API: BAPI_CUSTOMER_GETLIST
</code></pre>
<p>Fix P1 findings immediately. They block cloud deployment.</p>

<td>Unit test per determination</td>
<td>High</td>

<p><strong>Rule of thumb:</strong> Test every validation and every action. These contain your business logic. CDS views and behavior definitions are declarative — they're less likely to have bugs.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Not using test doubles</strong> — Testing against real database tables makes tests slow and fragile. Always use <code>cl_cds_test_environment</code> or <code>cl_botd_txn_buf_test_env</code>.</li>
<li><strong>Testing framework behavior</strong> — Don't test that CRUD works (the framework handles it). Test YOUR code — validations, determinations, actions.</li>
<li><strong>Ignoring ATC P1 findings</strong> — Priority 1 findings mean your code won't run in ABAP Cloud. Fix them immediately.</li>
<li><strong>Testing only happy paths</strong> — Test error cases too: empty fields, invalid references, wrong status transitions.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>ABAP Unit tests validate your business logic (validations, determinations, actions) automatically.</li>
<li>Use RAP test doubles to isolate tests from the database and other dependencies.</li>
<li>ATC with ABAP_CLOUD_DEVELOPMENT check variant ensures clean core compliance.</li>
<li>Test structure: Given (set up) → When (execute) → Then (assert).</li>
<li>Target zero P1/P2 ATC findings. Priority 3 findings are style improvements.</li>
</ul>
