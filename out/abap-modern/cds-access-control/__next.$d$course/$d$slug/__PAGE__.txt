</div><h2 id="from-authority-check-to-dcl">From AUTHORITY-CHECK to DCL</h2>
<p>In Classic ABAP, authorization was imperative — you wrote checks in your code:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" CLASSIC — authorization scattered throughout code</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">AUTHORITY-CHECK</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> OBJECT</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'Z_TM_ORD'</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  ID</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'ACTVT'</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> FIELD</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> '03'</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  ID</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'ZREGION'</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> FIELD</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ls_order-region.</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">IF</span><span style="--shiki-light:#005CC5;--shiki-dark:#E5C07B"> sy</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">-</span><span style="--shiki-light:#005CC5;--shiki-dark:#E5C07B">subrc</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> &#x3C;></span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> 0</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  RAISE</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> EXCEPTION TYPE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> cx_tm_not_authorized.</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">ENDIF</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span></code></pre>
<p>Problems: developers forget to add checks, checks are inconsistent across programs, and there's no central view of who can see what.</p>
<p>CDS access control is <strong>declarative</strong> — you define rules once, attached to the CDS view, and they apply everywhere the view is accessed.</p>
<h2 id="creating-an-access-control-object">Creating an Access Control Object</h2>
<p>In ADT: Right-click package → <strong>New → Access Control</strong></p>
<p>Name: <code>ZI_TM_SalesOrder</code> (same name as the CDS view it protects)</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">@EndUserText</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.label: </span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">'Access Control for Sales Orders'</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">@MappingRole</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: true</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">DEFINE </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">ROLE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ZI_TM_SalesOrder {</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  GRANT</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> SELECT</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> ON</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ZI_TM_SalesOrder</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  WHERE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ( Country ) </span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2">=</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    ASPECT pfcg_auth ( Z_TM_ORD, ZREGION, ACTVT </span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2">=</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> '03'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> );</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">}</span></span></code></pre>
<p>This means: a user can only SELECT rows from <code>ZI_TM_SalesOrder</code> where the <code>Country</code> field matches their authorization value for object <code>Z_TM_ORD</code>, field <code>ZREGION</code>, with activity <code>03</code> (display).</p>
<p>The access control applies automatically — every SELECT from this CDS view filters rows based on the user's authorization. No application code needed.</p>
<h2 id="how-dcl-rules-work">How DCL Rules Work</h2>
<p>The DCL rule acts as an invisible WHERE clause:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">" What the developer writes:</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">SELECT * FROM ZI_TM_SalesOrder INTO TABLE @DATA(lt_orders).</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> What actually executes (</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">for</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> a user authorized </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">for</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> region </span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">'US'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">):</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">SELECT</span><span style="--shiki-light:#D73A49;--shiki-dark:#ABB2BF"> *</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> FROM</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ZI_TM_SalesOrder </span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  WHERE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> Country </span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2">=</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'US'</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  INTO</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TABLE</span><span style="--shiki-light:#24292E;--shiki-dark:#E06C75"> @DATA</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(lt_orders).</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">" For a user authorized for 'US' and 'DE':</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">SELECT * FROM ZI_TM_SalesOrder </span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  WHERE Country IN ('US', 'DE')</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  INTO TABLE @DATA(lt_orders).</span></span></code></pre>
<p>The developer doesn't see the filter. It's applied by the framework.</p>

<h2 id="unrestricted-access-for-development">Unrestricted Access (for Development)</h2>
<p>During development, you might want all rows visible:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">@EndUserText</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.label: </span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">'Unrestricted Access for Development'</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">@MappingRole</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: true</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">DEFINE </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">ROLE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ZI_TM_SalesOrder {</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  GRANT</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> SELECT</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> ON</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ZI_TM_SalesOrder</span></span>

<h2 id="inherited-access-control">Inherited Access Control</h2>
<p>If <code>ZI_TM_SalesOrder</code> has access control, what about its child <code>ZI_TM_SalesOrderItem</code>? You can inherit:</p>

<h2 id="the-accesscontrol-annotation">The @AccessControl Annotation</h2>
<p>Every CDS view has this annotation controlling authorization behavior:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">@AccessControl</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.authorizationCheck: #</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">CHECK</span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">        -- DCL is required, enforced</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">@AccessControl</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.authorizationCheck: #NOT_REQUIRED  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">-- No DCL needed (open access)</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">@AccessControl</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.authorizationCheck: #NOT_ALLOWED   </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">-- DCL must NOT exist</span></span></code></pre>
<p>Use <code>#CHECK</code> for production views. Use <code>#NOT_REQUIRED</code> during development (as we've done throughout this course).</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Leaving <code>#NOT_REQUIRED</code> in production</strong> — This means no authorization filter. Every user sees every row. Always switch to <code>#CHECK</code> with a proper DCL before go-live.</li>
<li><strong>DCL name mismatch</strong> — The access control object MUST have the same name as the CDS view it protects. If the view is <code>ZI_TM_SalesOrder</code>, the DCL must also be <code>ZI_TM_SalesOrder</code>.</li>
<li><strong>Forgetting to test with different users</strong> — Access control is invisible to the developer who has full authorization. Always test with a restricted user.</li>
<li><strong>Over-complex DCL rules</strong> — Keep rules simple. If you need complex multi-table authorization, consider restructuring your CDS views.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>CDS access control (DCL) replaces AUTHORITY-CHECK with declarative, view-level row filtering.</li>
<li>Rules are defined once and apply everywhere the view is accessed — no code changes needed.</li>
<li>DCL objects must have the same name as the CDS view they protect.</li>
<li>Use <code>@AccessControl.authorizationCheck: #CHECK</code> for production, <code>#NOT_REQUIRED</code> for development.</li>
<li>Child entities can inherit parent access control, ensuring consistent authorization.</li>
</ul>
