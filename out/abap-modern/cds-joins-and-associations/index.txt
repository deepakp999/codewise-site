</div><h2 id="joins-in-cds--familiar-but-cleaner">Joins in CDS — Familiar but Cleaner</h2>
<p>You know SQL joins from Classic ABAP. CDS joins are the same concept:</p>

<h2 id="associations--lazy-joins">Associations — Lazy Joins</h2>
<p>Associations define a <strong>relationship</strong> without executing a join. The join only happens when you actually access the associated data:</p>

<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">    ON</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> $</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">projection</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">CustomerId</span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2"> =</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> _Customer</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">CustomerId</span></span>

<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  key</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> so</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">order_id</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">   AS</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> OrderId,</span></span>

<span class="line"><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">      so</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">status</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">      AS</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> Status</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">,</span></span>

<p>Key differences from joins:</p>
<ul>
<li>The association target is another <strong>CDS view</strong> (not a table)</li>
<li>The prefix <code>_</code> is the naming convention for associations</li>
<li>The join only fires when you access <code>_Customer</code> fields</li>
<li>The association is exposed as a navigation path</li>
</ul>
<h3 id="using-associations-in-abap-sql">Using Associations in ABAP SQL</h3>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Only order data — NO join to customer</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">SELECT</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> OrderId, Status </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">FROM</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ZI_TM_SalesOrder</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  INTO TABLE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> @</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DATA</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">lt_orders</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">).</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Order + customer name — NOW the join fires</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">SELECT</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> OrderId, Status, \_Customer-CustomerName</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  FROM</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ZI_TM_SalesOrder</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  INTO TABLE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> @</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DATA</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">lt_orders_with_cust</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">).</span></span></code></pre>
<p>The backslash-underscore syntax (<code>\_Customer-CustomerName</code>) is a <strong>path expression</strong>. It navigates the association and triggers the join.</p>
<h2 id="cardinality--how-many-related-rows">Cardinality — How Many Related Rows?</h2>
<p>Cardinality tells the framework the expected ratio between parent and associated rows:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">" One order has exactly one customer (or none)</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">ASSOCIATION [0..1] TO ZI_TM_Customer AS _Customer</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  ON $projection.CustomerId = _Customer.CustomerId</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">"</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> One order has zero </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">or</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> many </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">line</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> items</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">ASSOCIATION </span><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">[0..*]</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TO</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ZI_TM_SalesOrderItem </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">AS</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> _Items</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  ON</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> $</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">projection</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">OrderId</span><span style="--shiki-light:#D73A49;--shiki-dark:#56B6C2"> =</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> _Items</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">OrderId</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">" One line item has exactly one product</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">ASSOCIATION [1..1] TO ZI_TM_Product AS _Product</span></span>
<span class="line"><span style="--shiki-light:#032F62;--shiki-dark:#98C379">  ON $projection.ProductId = _Product.ProductId</span></span></code></pre>
<table>
<thead>
<tr>
<th>Cardinality</th>
<th>Meaning</th>
<th>Example</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>[0..1]</code></td>
<td>Zero or one related row</td>
<td>Order → Customer (customer might not exist yet)</td>
</tr>
<tr>
<td><code>[1..1]</code></td>
<td>Exactly one related row</td>
<td>Line item → Product (product must exist)</td>
</tr>
<tr>
<td><code>[0..*]</code></td>
<td>Zero or many related rows</td>
<td>Order → Line items</td>
</tr>
<tr>
<td><code>[1..*]</code></td>
<td>One or many related rows</td>
<td>Customer → Orders (at least one)</td>
</tr>
</tbody>
</table>
<p>Getting cardinality right matters for performance. The framework uses it to choose optimal join strategies.</p>
<h2 id="when-to-use-joins-vs-associations">When to Use Joins vs Associations</h2>
<table>
<thead>
<tr>
<th>Use a JOIN when...</th>
<th>Use an ASSOCIATION when...</th>
</tr>
</thead>
<tbody>
<tr>
<td>You always need the joined data</td>
<td>The related data is sometimes needed</td>
</tr>
<tr>
<td>You need to filter on joined fields</td>
<td>You want to expose a navigation path</td>
</tr>
<tr>
<td>Performance requires a single query</td>
<td>You want on-demand loading</td>
</tr>
<tr>
<td>Combining data for aggregation</td>
<td>Building a reusable data model</td>
</tr>
</tbody>
</table>
<p><strong>Rule of thumb:</strong> Use associations by default. Use joins only when you always need the data and performance requires it.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Defining associations ON table fields instead of $projection</strong> — Use <code>$projection.FieldAlias</code> in association conditions, not the raw table field names.</li>
<li><strong>Wrong cardinality</strong> — <code>[1..1]</code> means the framework expects exactly one match. If zero matches are possible, use <code>[0..1]</code> to avoid runtime errors.</li>
<li><strong>Not exposing associations</strong> — If you define <code>_Customer</code> but don't list it in the field list, it's invisible to consumers.</li>
<li><strong>Joining tables directly instead of CDS views</strong> — Best practice is to associate TO another CDS view (<code>ZI_TM_Customer</code>), not directly to a table. This keeps the layering clean.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Associations are lazy joins — they define relationships without executing them until needed.</li>
<li>Path expressions (<code>\_Association-Field</code>) navigate associations in ABAP SQL.</li>
<li>Cardinality (<code>[0..1]</code>, <code>[0..*]</code>, etc.) describes expected row counts and affects performance.</li>
<li>Use associations by default, joins only when you always need the data.</li>
<li>Associations target CDS views, not tables. This keeps your data model layered.</li>
</ul>
