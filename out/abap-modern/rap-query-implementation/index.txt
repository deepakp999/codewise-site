1b:T5cf2,<h1 id="rap-query--read-only-access-patterns">RAP Query — Read-Only Access Patterns</h1>
<div data-cw-section="learn-box"><h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>When to use RAP query (vs managed/unmanaged)</li>
<li>Implementing a custom query class</li>
<li>Handling pagination, filtering, and sorting</li>
<li>Connecting to non-database sources</li>
<li>TechMart's product analytics dashboard</li>
</ul>
</div><h2 id="when-to-use-query">When to Use Query</h2>
<p>RAP query is the right choice when:</p>
<ul>
<li>Data is <strong>read-only</strong> — no create, update, or delete</li>
<li>Data comes from a <strong>custom source</strong> (API, calculation, aggregation)</li>
<li>You need a <strong>custom query</strong> that CDS alone can't express</li>
<li>Building <strong>analytical dashboards</strong> or reports</li>
</ul>
<p>For TechMart's product analytics — aggregated sales by category, revenue trends, stock alerts — query is the perfect pattern.</p>

<h2 id="exposing-the-query">Exposing the Query</h2>
<p>Service definition and binding work exactly like managed/unmanaged:</p>
<pre><code>define service ZSD_TM_ANALYTICS {
  expose ZI_TM_ProductAnalytics as ProductAnalytics;
}
</code></pre>
<p>Bind it to OData V4 and preview. You get a read-only Fiori list report.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Using query for simple CDS aggregations</strong> — If a CDS view with GROUP BY can express the query, use a CDS analytical query instead. Custom query is for when CDS isn't enough.</li>
<li><strong>Ignoring pagination</strong> — Without pagination support, large result sets cause timeouts. Always implement <code>get_page_size()</code> and <code>get_offset()</code>.</li>
<li><strong>Not setting total count</strong> — Fiori needs <code>set_total_number_of_records()</code> for "Showing 1-20 of 342" display.</li>
<li><strong>Hardcoding filters</strong> — Read filters from <code>io_request->get_filter()</code> and apply them dynamically.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>RAP query is for read-only data from custom sources — analytics, aggregations, external APIs.</li>
<li>Custom entities define the structure. A query provider class fetches the data.</li>
<li>Implement <code>if_rap_query_provider~select</code> with support for filtering, sorting, and pagination.</li>
<li>Expose via service definition + binding, just like managed/unmanaged BOs.</li>
<li>Use CDS views when possible; custom queries when CDS isn't sufficient.</li>
</ul>
