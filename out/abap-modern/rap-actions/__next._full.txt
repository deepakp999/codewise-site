1b:T7070,<h1 id="actions--static-instance-and-factory-actions">Actions — Static, Instance, and Factory Actions</h1>
<div data-cw-section="learn-box"><h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>What actions are and the three types</li>
<li>Instance actions: operations on a specific record</li>
<li>Static actions: operations without selecting a record</li>
<li>Factory actions: creating new records from existing ones</li>
<li>Action parameters and result types</li>
</ul>
</div><h2 id="what-are-actions">What Are Actions?</h2>
<p>Actions are custom operations beyond standard CRUD. They appear as buttons in the Fiori UI. TechMart needs:</p>
<ul>
<li><strong>Approve Order</strong> — change status from New to Approved (instance action)</li>
<li><strong>Create with Reference</strong> — copy an existing order (factory action)</li>
<li><strong>Generate Daily Report</strong> — runs without selecting an order (static action)</li>
</ul>
<h2 id="instance-action--approve-order">Instance Action — Approve Order</h2>
<p>An instance action operates on a selected record.</p>
<p><strong>Step 1: Declare in behavior definition</strong></p>
<pre><code>define behavior for ZI_TM_SalesOrder alias SalesOrder
{
  ...
  action approve result [1] $self;
}
</code></pre>
<p><code>result [1] $self</code> means the action returns the updated instance.</p>

<h2 id="actions-with-parameters">Actions with Parameters</h2>
<p>Actions can accept input. Define an abstract entity for the parameter:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">@EndUserText</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.label: </span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">'Rejection Reason'</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">DEFINE ABSTRACT ENTITY ZA_TM_RejectParams</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">{</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">  Reason : </span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">abap</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">string</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">200</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">);</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">}</span></span></code></pre>

<pre><code>action rejectOrder parameter ZA_TM_RejectParams result [1] $self;
</code></pre>

<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">METHOD</span><span style="--shiki-light:#6F42C1;--shiki-dark:#61AFEF"> rejectOrder</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>

<h2 id="exposing-actions-in-the-projection">Exposing Actions in the Projection</h2>
<p>Actions declared at the interface level must be exposed in the projection:</p>
<pre><code>projection;
define behavior for ZC_TM_SalesOrder alias SalesOrder
{
  use action approve;
  use action copyOrder;
  use action rejectOrder;
  use static action generateReport;
}
</code></pre>
<p>And add UI annotations to show the button:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">@UI</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.lineItem: [{ </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">type</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: #FOR_ACTION, dataAction: </span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">'approve'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">,</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">                  label: </span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">'Approve'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">, position: </span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66">10</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> }]</span></span></code></pre>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Instance action on multiple selections</strong> — RAP actions receive a table of keys. Loop through all of them, don't just process <code>keys[ 1 ]</code>.</li>
<li><strong>Forgetting to return result</strong> — If the behavior definition says <code>result [1] $self</code>, the method MUST populate the <code>result</code> parameter. Otherwise the Fiori UI won't refresh.</li>
<li><strong>Not exposing in projection</strong> — An action declared at the interface level but not exposed in the projection behavior won't appear in the Fiori app.</li>
<li><strong>Mixing action and validation logic</strong> — Actions should execute operations. Put data validation in validations, not in actions.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Actions are custom operations beyond CRUD — they appear as buttons in Fiori.</li>
<li>Instance actions operate on selected records. Static actions don't need selection. Factory actions create new records.</li>
<li>Use abstract entities for action parameters (user input).</li>
<li>Actions must be exposed in the projection behavior with <code>use action</code>.</li>
<li>Add <code>@UI.lineItem</code> annotations with <code>type: #FOR_ACTION</code> to display action buttons.</li>
</ul>
