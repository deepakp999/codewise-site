</div><h2 id="why-parameters">Why Parameters?</h2>
<p>A regular CDS view always returns the same columns and structure. Filtering happens in the WHERE clause of the consuming ABAP SQL. But sometimes the logic inside the view itself needs to change based on input — a reference date for aging calculations, a target currency for conversion, a fiscal year for period selection.</p>
<p>Parameters let you pass values INTO the CDS view definition, not just filter the output.</p>

<h2 id="when-to-use-parameters-vs-where">When to Use Parameters vs WHERE</h2>
<table>
<thead>
<tr>
<th>Use Parameters when...</th>
<th>Use WHERE when...</th>
</tr>
</thead>
<tbody>
<tr>
<td>The view logic itself changes (calculations, CASE)</td>
<td>You just need to filter output rows</td>
</tr>
<tr>
<td>You need to pass values to associated views</td>
<td>The filter is simple equality/range</td>
</tr>
<tr>
<td>The view represents a function with inputs</td>
<td>The view represents a data set</td>
</tr>
<tr>
<td>Currency/unit conversion needs a target</td>
<td>You're filtering on existing columns</td>
</tr>
</tbody>
</table>
<p><strong>Rule of thumb:</strong> If removing the filter would change the <em>meaning</em> of the view (not just the number of rows), use a parameter.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Too many parameters</strong> — If your view has 8 parameters, it's too complex. Split it into multiple focused views.</li>
<li><strong>Forgetting <code>$parameters.</code></strong> — Parameters in the view body must be prefixed with <code>$parameters.</code>. Without it, the system looks for a field name.</li>
<li><strong>Using parameters where WHERE suffices</strong> — If you just want orders for customer X, add a WHERE clause in ABAP SQL. Don't create a parameter for it.</li>
<li><strong>Parameter type mismatches</strong> — The ABAP SQL call must pass values matching the parameter type exactly. <code>p_date_from = '2026-01-01'</code> fails — use <code>'20260101'</code> (DATS format).</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Parameters let you pass runtime values INTO CDS view logic — calculated fields, CASE expressions, WHERE conditions.</li>
<li>Access parameters with <code>$parameters.name</code> in the view body.</li>
<li>Call parameterized views with <code>SELECT FROM ViewName( param = value )</code>.</li>
<li>Use <code>@Environment.systemField</code> for auto-filled defaults.</li>
<li>Parameters are for view logic; WHERE is for output filtering. Don't overuse parameters.</li>
</ul>
