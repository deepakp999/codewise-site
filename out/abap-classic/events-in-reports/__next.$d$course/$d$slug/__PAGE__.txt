</div><h2 id="the-report-execution-flow">The Report Execution Flow</h2>
<p>ABAP reports don't just run top to bottom like a Python script. They follow an event-driven model where SAP calls different blocks of your code at different stages:</p>
<pre><code>Program starts
    ↓
LOAD-OF-PROGRAM          (rarely used — program loading)
    ↓
INITIALIZATION            (set dynamic defaults)
    ↓
Selection screen appears → user fills in values
    ↓
AT SELECTION-SCREEN       (validate input)
    ↓
User clicks Execute (F8)
    ↓
START-OF-SELECTION        (main processing — your core logic)
    ↓
END-OF-SELECTION          (final output, cleanup)
    ↓
Output list appears
    ↓
TOP-OF-PAGE               (called before each new page of output)
</code></pre>

<h2 id="event-descriptions">Event Descriptions</h2>
<h3 id="initialization">INITIALIZATION</h3>
<p>Fires once when the program starts, before the selection screen appears. Use it to set dynamic defaults — for example, setting the default date range to "last 30 days."</p>
<h3 id="at-selection-screen">AT SELECTION-SCREEN</h3>
<p>Fires when the user clicks Execute on the selection screen. Use it to validate input. If you raise a TYPE 'E' message, the user stays on the selection screen.</p>
<h3 id="start-of-selection">START-OF-SELECTION</h3>
<p>The main event — this is where your core logic goes. Database reads, transformations, calculations, and primary output. If you don't specify any events, all code after the selection screen definitions implicitly runs in START-OF-SELECTION.</p>
<h3 id="end-of-selection">END-OF-SELECTION</h3>
<p>Fires after START-OF-SELECTION completes. Use it for summaries, totals, footer information, or cleanup tasks like freeing memory or closing files.</p>
<h3 id="top-of-page">TOP-OF-PAGE</h3>
<p>Fires before the first WRITE on each new page of output. Use it for page headers:</p>

<p>If your program doesn't use a selection screen (no PARAMETERS or SELECT-OPTIONS), you don't need events at all — code runs top to bottom:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">REPORT</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> z_simple.</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">WRITE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">/</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'This runs immediately — no events needed'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span></code></pre>
<p>But the moment you add a PARAMETERS line, the event model kicks in. Code before START-OF-SELECTION runs during initialization. Code after runs during main processing. Being explicit with events makes your code clearer.</p>

<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Putting database SELECTs in INITIALIZATION.</strong> INITIALIZATION runs before the user enters anything — reading the database here wastes resources if the user cancels. Put SELECTs in START-OF-SELECTION.</li>
<li><strong>Forgetting that code without events runs in START-OF-SELECTION.</strong> If you have a PARAMETERS line but no explicit events, your WRITE statements run after the user clicks Execute. This is implicit and can be confusing.</li>
<li><strong>Using TOP-OF-PAGE with ALV reports.</strong> TOP-OF-PAGE only works with classical WRITE output. ALV reports (Lessons 21-22) handle headers differently.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>ABAP reports use an event-driven model: INITIALIZATION → AT SELECTION-SCREEN → START-OF-SELECTION → END-OF-SELECTION.</li>
<li>START-OF-SELECTION is where your main logic goes — database reads, processing, output.</li>
<li>INITIALIZATION sets dynamic defaults. AT SELECTION-SCREEN validates input.</li>
<li>END-OF-SELECTION handles summaries and cleanup.</li>
<li>Be explicit with events — it makes your code structure clear and maintainable.</li>
</ul>
