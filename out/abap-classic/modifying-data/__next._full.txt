<h2 id="commit-work-and-rollback-work">COMMIT WORK and ROLLBACK WORK</h2>
<p>Database changes in ABAP are transactional. They're not visible to other users until you COMMIT:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* Make changes</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">INSERT</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> zemployees </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">FROM</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ls_emp_new.</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">UPDATE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> zemployees </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">FROM</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ls_emp_updated.</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DELETE</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> FROM</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> zemployees </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">WHERE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> employee_id </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">=</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> '0000000099'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* Make changes permanent</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">COMMIT</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> WORK</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* Or undo all changes since last commit</span></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* ROLLBACK WORK.</span></span></code></pre>
<p><strong>Coming from Python/SQL:</strong> This is like <code>connection.commit()</code> in Python's DB-API. Without COMMIT WORK, changes are in a pending state and can be rolled back.</p>
<p><strong>Important:</strong> In most SAP applications, you don't call COMMIT WORK directly. SAP's framework handles it — when a user saves a transaction, SAP commits. Custom programs that run independently (background jobs, interfaces) do need explicit COMMIT WORK.</p>
<h3 id="commit-work-and-wait">COMMIT WORK AND WAIT</h3>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">COMMIT</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> WORK</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> AND</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> WAIT</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Waits until the commit is confirmed by the database</span></span></code></pre>
<p>Use <code>AND WAIT</code> when subsequent code depends on the committed data being available.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Forgetting COMMIT WORK in standalone programs.</strong> Without it, your INSERTs and UPDATEs are lost when the program ends. SAP reports that run via SE38 auto-commit on exit, but background jobs and RFC functions do not.</li>
<li><strong>Using single INSERT/UPDATE in a loop.</strong> <code>LOOP AT lt_data. INSERT dbtable FROM ls_data. ENDLOOP.</code> makes one database call per row. Use <code>INSERT dbtable FROM TABLE lt_data</code> for one call total — 100x faster on large datasets.</li>
<li><strong>Not checking sy-subrc after INSERT.</strong> If the primary key exists, INSERT fails silently (sy-subrc = 4). Your program continues, thinking the data was saved.</li>
<li><strong>Using DELETE without a WHERE clause by accident.</strong> <code>DELETE FROM ztable.</code> deletes ALL records. Always double-check your WHERE condition before running DELETE on production tables.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>INSERT adds new records (fails if key exists). UPDATE modifies existing (fails if key missing). MODIFY does both (upsert).</li>
<li>DELETE removes by key or condition. Always verify the WHERE clause.</li>
<li>Use bulk operations (FROM TABLE) instead of loops — dramatically faster.</li>
<li>COMMIT WORK makes changes permanent. ROLLBACK WORK undoes them.</li>
<li><code>sy-subrc</code> reports success/failure. <code>sy-dbcnt</code> reports the number of affected rows.</li>
<li>Never forget COMMIT WORK in background jobs and interface programs.</li>
</ul>
