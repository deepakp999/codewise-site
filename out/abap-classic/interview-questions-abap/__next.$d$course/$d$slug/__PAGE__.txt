</div><h2 id="beginner-level">Beginner Level</h2>
<h3 id="1-what-is-abap-and-what-is-it-used-for">1. What is ABAP and what is it used for?</h3>
<p>ABAP (Advanced Business Application Programming) is SAP's proprietary language for developing and customizing applications on the SAP platform. It's used to build custom reports, extend standard SAP functionality, create interfaces between SAP and external systems, and migrate data. ABAP runs on the SAP Application Server, between the user interface and the database.</p>
<p><em>Covered in: Lesson 1</em></p>
<h3 id="2-what-are-the-different-data-types-in-abap">2. What are the different data types in ABAP?</h3>
<p>Elementary types: <code>i</code> (integer), <code>f</code> (float), <code>p</code> (packed decimal for financial data), <code>c</code> (fixed-length character), <code>string</code> (variable-length), <code>n</code> (numeric text preserving leading zeros), <code>d</code> (date YYYYMMDD), <code>t</code> (time HHMMSS), <code>x</code> (hexadecimal). Use <code>p DECIMALS n</code> for money — never <code>f</code>, which has floating-point rounding errors.</p>
<p><em>Covered in: Lesson 6</em></p>
<h3 id="3-what-is-an-internal-table-name-the-three-types">3. What is an internal table? Name the three types.</h3>
<p>An internal table is an in-memory data structure for holding multiple rows of structured data. Three types: <strong>STANDARD</strong> (sequential access, like a list), <strong>SORTED</strong> (binary search access by key), <strong>HASHED</strong> (constant-time access by key, like a dictionary). STANDARD is the default and most common.</p>
<p><em>Covered in: Lesson 9</em></p>
<h3 id="4-what-is-the-difference-between-append-and-insert-for-internal-tables">4. What is the difference between APPEND and INSERT for internal tables?</h3>
<p><code>APPEND</code> adds a row to the end of a STANDARD table. <code>INSERT</code> adds a row at a specific position or maintains sort order in a SORTED table. You cannot use APPEND on SORTED or HASHED tables — use INSERT.</p>
<p><em>Covered in: Lesson 10</em></p>
<h3 id="5-what-is-sy-subrc-and-why-is-it-important">5. What is sy-subrc and why is it important?</h3>
<p><code>sy-subrc</code> is a system variable that indicates the return code of the last operation. <code>0</code> means success, non-zero means failure (usually <code>4</code>). You must check <code>sy-subrc</code> after: SELECT, READ TABLE, CALL FUNCTION, OPEN DATASET, and most other operations. Not checking <code>sy-subrc</code> is one of the most common bugs in ABAP.</p>
<p><em>Covered in: Lesson 6</em></p>
<h2 id="intermediate-level">Intermediate Level</h2>
<h3 id="6-what-is-the-difference-between-a-field-symbol-and-a-work-area">6. What is the difference between a field symbol and a work area?</h3>
<p>A work area (<code>INTO ls_work</code>) creates a copy of the data — changes don't affect the original table. A field symbol (<code>ASSIGNING &#x3C;ls_fs></code>) points directly to the memory — changes immediately affect the table. Field symbols are faster (no copy overhead) and preferred for modifying data in loops.</p>

<h3 id="7-what-is-for-all-entries-and-what-is-the-critical-rule">7. What is FOR ALL ENTRIES and what is the critical rule?</h3>
<p>FOR ALL ENTRIES reads database records matching entries in a driver internal table — like a batch WHERE IN clause. <strong>Critical rule:</strong> Always check that the driver table is NOT INITIAL before using FOR ALL ENTRIES. If the driver table is empty, SAP ignores the WHERE clause and returns ALL records from the database.</p>
<p><em>Covered in: Lesson 15</em></p>
<h3 id="8-what-is-the-difference-between-commit-work-and-bapi_transaction_commit">8. What is the difference between COMMIT WORK and BAPI_TRANSACTION_COMMIT?</h3>
<p><code>COMMIT WORK</code> is the standard ABAP statement for committing database changes. <code>BAPI_TRANSACTION_COMMIT</code> is a function module that wraps COMMIT WORK with BAPI-specific logic. After calling a BAPI, always use <code>BAPI_TRANSACTION_COMMIT</code> — it ensures all BAPI-internal update tasks are processed correctly.</p>
<p><em>Covered in: Lessons 16 and 24</em></p>
<h3 id="9-explain-the-sap-transport-system">9. Explain the SAP transport system.</h3>
<p>Code is written in DEV, tested in QAS, and deployed to PRD. Changes are packaged in <strong>transport requests</strong> — containers holding code, table definitions, and configuration. Transports move forward only (DEV → QAS → PRD, never backward). Transport requests are managed in SE09/SE10 and imported by the Basis team.</p>
<p><em>Covered in: Lesson 2</em></p>
<h3 id="10-what-is-a-bapi-how-does-it-differ-from-a-regular-function-module">10. What is a BAPI? How does it differ from a regular function module?</h3>
<p>A BAPI (Business Application Programming Interface) is an SAP-standard, RFC-enabled function module with a formal interface following SAP conventions. BAPIs have a RETURN parameter (BAPIRET2) for error messages, support transaction handling (BAPI_TRANSACTION_COMMIT), and are upgrade-stable. Regular function modules don't follow these conventions.</p>
<p><em>Covered in: Lesson 24</em></p>
<h3 id="11-what-is-alv-name-two-approaches">11. What is ALV? Name two approaches.</h3>
<p>ALV (ABAP List Viewer) is SAP's standard framework for displaying tabular data with built-in sorting, filtering, totals, and Excel export. Two approaches: <strong>REUSE_ALV_GRID_DISPLAY</strong> (function module, older) and <strong>CL_SALV_TABLE</strong> (OOP class, modern and recommended).</p>
<p><em>Covered in: Lessons 21 and 22</em></p>
<h3 id="12-what-is-a-selection-screen">12. What is a selection screen?</h3>
<p>A selection screen is a user input form displayed before a report executes. It's built with <code>PARAMETERS</code> (single values) and <code>SELECT-OPTIONS</code> (ranges/multiple values). SELECT-OPTIONS generate RANGE tables used in SELECT WHERE ... IN clauses. Input validation happens in the <code>AT SELECTION-SCREEN</code> event.</p>
<p><em>Covered in: Lesson 18</em></p>
<h2 id="advanced-level">Advanced Level</h2>
<h3 id="13-what-is-the-difference-between-user-exits-customer-exits-and-badis">13. What is the difference between user exits, customer exits, and BADIs?</h3>
<p>All are enhancement mechanisms to extend SAP standard code without modification. <strong>User exits</strong> are FORM-based (oldest, limited). <strong>Customer exits</strong> are function-module-based (SMOD/CMOD, more flexible). <strong>BADIs</strong> are OOP-based (SE18/SE19, most modern and recommended). BADIs support filters, multiple implementations, and fallback classes.</p>
<p><em>Covered in: Lesson 29</em></p>
<h3 id="14-what-is-an-idoc">14. What is an IDoc?</h3>
<p>An IDoc (Intermediate Document) is a standard SAP data format for asynchronous document exchange between systems. Structure: Control Record (routing metadata) + Data Records (business data in segments) + Status Records (processing audit trail). IDocs are used for EDI, ALE master data distribution, and integration with non-SAP systems via middleware.</p>
<p><em>Covered in: Lesson 26</em></p>
<h3 id="15-what-is-rfc-name-the-three-types">15. What is RFC? Name the three types.</h3>
<p>RFC (Remote Function Call) is SAP's protocol for calling function modules across systems. <strong>sRFC</strong> (synchronous — caller waits for response), <strong>aRFC</strong> (asynchronous — fire and forget), <strong>tRFC</strong> (transactional — guaranteed exactly-once delivery with automatic retry). tRFC requires COMMIT WORK to actually send queued calls.</p>
<p><em>Covered in: Lesson 25</em></p>
<h3 id="16-how-do-you-debug-an-abap-program">16. How do you debug an ABAP program?</h3>
<p>Set breakpoints (click in margin, <code>BREAK-POINT</code> statement, or <code>/h</code> in command field). Use F5 (step into), F6 (step over), F7 (return), F8 (continue). Inspect variables by double-clicking them. Use watchpoints to break when a value changes. View short dumps in ST22. Profile performance with SE30/SAT.</p>
<p><em>Covered in: Lesson 28</em></p>
<h3 id="17-what-is-the-abap-data-dictionary">17. What is the ABAP Data Dictionary?</h3>
<p>The Data Dictionary (SE11) is SAP's metadata layer defining all database tables, data elements, domains, structures, and table types. The hierarchy is: Domain (technical properties) → Data Element (semantic meaning) → Table Field (usage). Programs should reference dictionary types (<code>TYPE kunnr</code>) instead of raw types (<code>TYPE c LENGTH 10</code>).</p>
<p><em>Covered in: Lesson 13</em></p>
<h3 id="18-what-is-bdc-and-when-would-you-use-it">18. What is BDC and when would you use it?</h3>
<p>BDC (Batch Data Communication) simulates user transactions programmatically — filling screens and clicking buttons. Use it for data migration when no BAPI exists. Record transactions with SHDB, create a BDC program from the recording, and execute with <code>CALL TRANSACTION</code>. Always prefer BAPIs over BDC when available.</p>
<p><em>Covered in: Lesson 27</em></p>
<h3 id="19-what-are-the-differences-between-modify-update-and-insert">19. What are the differences between MODIFY, UPDATE, and INSERT?</h3>
<p><code>INSERT</code> adds a new record — fails if the primary key exists (<code>sy-subrc = 4</code>). <code>UPDATE</code> changes an existing record — fails if the key doesn't exist. <code>MODIFY</code> does both — inserts if the key doesn't exist, updates if it does (upsert). In production, prefer explicit INSERT/UPDATE over MODIFY for clarity.</p>
<p><em>Covered in: Lesson 16</em></p>
<h3 id="20-how-would-you-optimize-a-slow-abap-program">20. How would you optimize a slow ABAP program?</h3>
<ol>
<li>Profile with SE30/SAT to find the bottleneck</li>
<li>Replace SELECT inside LOOP with FOR ALL ENTRIES or JOINs</li>
<li>Select only needed fields (no <code>SELECT *</code>)</li>
<li>Use field symbols instead of work areas in loops</li>
<li>Use SORTED or HASHED tables for frequent key lookups</li>
<li>Use buffer tables for repeatedly accessed master data</li>
<li>Minimize database roundtrips — batch operations</li>
<li>Check indexes on database tables used in WHERE clauses</li>
</ol>
<p><em>Covered across: Lessons 9, 11, 15, 28</em></p>
<h2 id="interview-tips">Interview Tips</h2>
<ul>
<li><strong>Show you've worked with real SAP systems.</strong> Mention specific transactions (SE38, SE11, SE37, VA01) and table names (KNA1, VBAK, MARA). This proves practical experience.</li>
<li><strong>Always mention the safety check.</strong> When discussing FOR ALL ENTRIES, immediately say "check that the driver table is not initial." When discussing BAPIs, immediately mention BAPI_TRANSACTION_COMMIT. These show awareness of common pitfalls.</li>
<li><strong>Know the evolution.</strong> When asked about enhancements, explain the progression from user exits → customer exits → BADIs → Enhancement Framework. This shows depth.</li>
<li><strong>Reference debugging.</strong> When asked about any "how would you fix" scenario, start with "I'd check ST22 for dumps, then set a breakpoint at..." This shows you have practical debugging experience.</li>
</ul>
