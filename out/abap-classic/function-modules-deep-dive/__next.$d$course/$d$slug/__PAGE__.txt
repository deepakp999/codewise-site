</div><h2 id="what-are-function-modules">What Are Function Modules?</h2>
<p>Function modules are SAP's reusable code units — stored in the system dictionary, callable from any program, and discoverable via SE37. Think of them as globally available functions with a formal interface.</p>
<p>You've already called function modules (REUSE_ALV_GRID_DISPLAY, CONVERSION_EXIT_ALPHA_OUTPUT). Now let's build our own.</p>
<h2 id="creating-a-function-module-in-se37">Creating a Function Module in SE37</h2>
<h3 id="step-1-create-a-function-group">Step 1: Create a Function Group</h3>
<p>Function modules live in function groups — containers that share global data. In SE37, go to Function Group → Create:</p>
<ul>
<li><strong>Function Group:</strong> <code>Z_HR_UTILS</code></li>
<li><strong>Short Text:</strong> "HR Utility Functions"</li>
<li><strong>Package:</strong> <code>$TMP</code> (for learning)</li>
</ul>
<h3 id="step-2-create-the-function-module">Step 2: Create the Function Module</h3>
<p>In SE37, enter the name <code>Z_CALCULATE_BONUS</code> and click Create:</p>
<ul>
<li><strong>Function Group:</strong> <code>Z_HR_UTILS</code></li>
<li><strong>Short Text:</strong> "Calculate employee bonus based on salary and rating"</li>
</ul>
<h3 id="step-3-define-the-interface">Step 3: Define the Interface</h3>
<p>On the <strong>Import</strong> tab:</p>
<pre><code>Parameter Name    Type         Reference Type    Optional    Description
─────────────     ──────       ──────────────    ─────────   ───────────
IV_SALARY         TYPE         P DECIMALS 2      -           Annual salary
IV_RATING         TYPE         C LENGTH 1        -           Performance rating (A/B/C)
IV_YEARS          TYPE         I                 X           Years of service
</code></pre>
<p>On the <strong>Export</strong> tab:</p>
<pre><code>Parameter Name    Type         Reference Type    Description
─────────────     ──────       ──────────────    ───────────
EV_BONUS          TYPE         P DECIMALS 2      Calculated bonus amount
EV_BONUS_PCT      TYPE         P DECIMALS 1      Bonus percentage applied
</code></pre>
<p>On the <strong>Exceptions</strong> tab:</p>
<pre><code>Exception Name           Description
──────────────           ───────────
INVALID_RATING           Rating must be A, B, or C
SALARY_NOT_POSITIVE      Salary must be greater than zero
</code></pre>

<pre><code>Processing Type: Remote-Enabled Module
</code></pre>

<h2 id="function-group-global-data">Function Group Global Data</h2>
<p>Function modules in the same function group share global data:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* In the TOP include of function group Z_HR_UTILS:</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DATA</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: gv_company_code</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TYPE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> bukrs,</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">      gt_config      </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TYPE TABLE OF</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> zhrc_config.</span></span></code></pre>
<p>All function modules in Z_HR_UTILS can access <code>gv_company_code</code> and <code>gt_config</code>. This is useful for caching — load configuration once, share across all function calls.</p>
<h2 id="finding-standard-function-modules">Finding Standard Function Modules</h2>
<p>SE37 has a search function. Common ways to find the right function module:</p>
<ul>
<li><strong>Search by name:</strong> Use wildcards like <code>*CUSTOMER*CREATE*</code></li>
<li><strong>Search by function group:</strong> Browse function groups related to your module</li>
<li><strong>Google it:</strong> "SAP function module to create sales order" → results usually point you to the right FM</li>
<li><strong>SE37 documentation:</strong> Most SAP function modules have inline documentation</li>
</ul>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Not handling all exceptions.</strong> If a function module raises an exception you don't handle, <code>sy-subrc</code> gets a non-zero value but your program may not realize something went wrong. Always handle <code>OTHERS</code> as a catch-all.</li>
<li><strong>Passing the wrong parameter direction.</strong> IMPORTING parameters are input to the function module. EXPORTING parameters are output from it. This is from the function module's perspective — the caller EXPORTS to the FM's IMPORTING and IMPORTS from the FM's EXPORTING. The naming is backwards from the caller's point of view.</li>
<li><strong>Making a function module RFC-enabled without considering serialization.</strong> RFC-enabled function modules serialize all parameters across the network. Complex deep structures or large tables can cause performance issues over RFC.</li>
<li><strong>Using TABLES parameter instead of CHANGING.</strong> The TABLES parameter is legacy — it uses header lines, which are deprecated. Use CHANGING with a typed table for new function modules.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Function modules are reusable, callable from any program, and testable in SE37.</li>
<li>Interface has four categories: IMPORTING (in), EXPORTING (out), CHANGING (in+out), EXCEPTIONS (errors).</li>
<li>Always handle exceptions — at minimum, handle OTHERS as a catch-all.</li>
<li>RFC-enabled function modules can be called from remote systems and external programs.</li>
<li>Function groups share global data across their function modules — useful for caching.</li>
<li>Test function modules directly in SE37 (F8) before calling them from your program.</li>
</ul>
