</div><h2 id="what-is-a-bapi">What Is a BAPI?</h2>
<p>A BAPI (Business Application Programming Interface) is a standard SAP function module that provides a stable, documented interface to SAP business objects. BAPIs are SAP's official API layer — they're the supported way to create, read, change, and delete business data programmatically.</p>
<p><strong>BAPI vs regular function module:</strong> BAPIs follow SAP standards — consistent naming, RETURN parameter for messages, transaction handling, and upgrade stability. Regular function modules can be anything.</p>
<h2 id="finding-bapis">Finding BAPIs</h2>
<h3 id="method-1-bapi-explorer-transaction-bapi">Method 1: BAPI Explorer (Transaction BAPI)</h3>
<p>Type <code>/nBAPI</code> to open the BAPI Explorer. Browse by business object:</p>
<pre><code>Business Object Hierarchy:
├── Cross-Application
├── Sales and Distribution
│   ├── SalesOrder
│   │   ├── CreateFromDat2  → BAPI_SALESORDER_CREATEFROMDAT2
│   │   ├── GetList          → BAPI_SALESORDER_GETLIST
│   │   └── Change           → BAPI_SALESORDER_CHANGE
├── Materials Management
│   ├── PurchaseOrder
│   │   ├── Create1          → BAPI_PO_CREATE1
│   │   └── GetDetail        → BAPI_PO_GETDETAIL
├── Financial Accounting
│   ├── AcctngDocument
│   │   └── Post             → BAPI_ACC_DOCUMENT_POST
</code></pre>
<h3 id="method-2-search-in-se37">Method 2: Search in SE37</h3>
<p>Search for <code>BAPI_*</code> with wildcards: <code>BAPI_SALESORDER*</code>, <code>BAPI_CUSTOMER*</code>, <code>BAPI_MATERIAL*</code>.</p>

<h2 id="the-return-parameter--bapi-error-handling">The RETURN Parameter — BAPI Error Handling</h2>
<p>Every BAPI returns a <code>RETURN</code> table (type BAPIRET2) with messages:</p>
<pre><code>TYPE    Meaning
─────   ─────────────────
S       Success message
E       Error message
W       Warning message
I       Information message
A       Abort (critical error)
</code></pre>
<p><strong>Always check the RETURN table for errors.</strong> A BAPI call with <code>sy-subrc = 0</code> does NOT mean it succeeded — it only means the function module was called successfully. Business errors are reported in the RETURN table.</p>
<h2 id="bapi_transaction_commit--critical">BAPI_TRANSACTION_COMMIT — Critical!</h2>
<p>BAPIs don't commit data automatically. After a successful BAPI call, you MUST call:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">CALL</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> FUNCTION</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'BAPI_TRANSACTION_COMMIT'</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  EXPORTING</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">    wait</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> =</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'X'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.     </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Wait for commit to complete</span></span></code></pre>
<p>Without this call, the sales order, purchase order, or whatever you created is <strong>not saved to the database</strong>. This is the #1 BAPI mistake.</p>
<p>For errors, call:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">CALL</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> FUNCTION</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'BAPI_TRANSACTION_ROLLBACK'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span></code></pre>

<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Forgetting BAPI_TRANSACTION_COMMIT.</strong> Without it, no data is saved. This is the most common BAPI error — everything looks like it worked, but the data isn't there.</li>
<li><strong>Checking sy-subrc instead of the RETURN table.</strong> <code>sy-subrc = 0</code> after CALL FUNCTION means the FM was reached, not that the business operation succeeded. Always check RETURN for TYPE 'E' or 'A'.</li>
<li><strong>Not understanding the "X" structures.</strong> Many BAPIs have matching "X" structures (like <code>bapisdhd1x</code> for <code>bapisdhd1</code>). The X structure tells SAP which fields you're actually setting — without it, SAP ignores your values.</li>
<li><strong>Calling BAPI_TRANSACTION_COMMIT after an error.</strong> If the RETURN table contains errors, call ROLLBACK, not COMMIT. Committing after an error can leave data in an inconsistent state.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>BAPIs are SAP's official APIs — stable, documented, and upgrade-safe.</li>
<li>Always check the RETURN table for errors — <code>sy-subrc = 0</code> is not enough.</li>
<li>Always call BAPI_TRANSACTION_COMMIT after successful BAPIs, BAPI_TRANSACTION_ROLLBACK after errors.</li>
<li>Use the "X" structures to flag which fields you're populating.</li>
<li>Find BAPIs via BAPI Explorer (transaction BAPI) or by searching <code>BAPI_*</code> in SE37.</li>
</ul>
