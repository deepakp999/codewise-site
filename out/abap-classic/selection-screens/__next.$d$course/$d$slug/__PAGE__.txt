</div><h2 id="why-selection-screens">Why Selection Screens?</h2>
<p>Every business report needs user input: "Show me sales orders from January to March for customer X." Selection screens are ABAP's built-in way to collect this input before the report runs.</p>
<p>When you run a report with F8, SAP displays the selection screen first. The user fills in parameters, clicks Execute, and the report processes data based on those inputs.</p>

<p>The <code>FOR</code> keyword tells SAP which field the SELECT-OPTION is based on — it inherits the type, F4 help, and description from that field. The user can enter:</p>
<ul>
<li>A single value: <code>1001</code></li>
<li>A range: <code>1001</code> to <code>1999</code></li>
<li>Multiple values (click the multiple selection button)</li>
<li>Exclusions (toggle Include/Exclude)</li>
</ul>
<p>Internally, each SELECT-OPTION is a RANGE table — exactly what we learned in Lesson 17.</p>

<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Not using OBLIGATORY for critical fields.</strong> If your report crashes without a customer number, make it mandatory. Users will submit empty selection screens and wonder why nothing happens.</li>
<li><strong>Forgetting to use IN for SELECT-OPTIONS in SELECT statements.</strong> <code>WHERE kunnr = s_kunnr</code> doesn't work — s_kunnr is a range table. Use <code>WHERE kunnr IN s_kunnr</code>.</li>
<li><strong>Not validating input in AT SELECTION-SCREEN.</strong> If a user enters a non-existent customer number, the report runs and returns zero results. Validate and show an error message instead.</li>
<li><strong>Using PARAMETERS when SELECT-OPTIONS would be better.</strong> If users ever need to enter multiple values or a range, use SELECT-OPTIONS. PARAMETERS only accepts one value.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>PARAMETERS create single-value input fields. SELECT-OPTIONS create range inputs.</li>
<li>SELECT-OPTIONS generate RANGE tables — use with <code>WHERE field IN s_option</code> in SELECT statements.</li>
<li>OBLIGATORY makes a field required. AS CHECKBOX and RADIOBUTTON GROUP change the control type.</li>
<li>Group related fields in SELECTION-SCREEN BLOCK for visual organization.</li>
<li>Validate input in the <code>AT SELECTION-SCREEN</code> event — show errors before the report runs.</li>
<li>Use <code>INITIALIZATION</code> to set dynamic defaults when the screen first appears.</li>
</ul>
