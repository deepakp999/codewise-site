1b:T4c8b,<h1 id="rfc--remote-function-calls">RFC — Remote Function Calls</h1>
<div data-cw-section="learn-box"><h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>What RFC is and why it's SAP's primary integration mechanism</li>
<li>The three RFC types: synchronous, asynchronous, and transactional</li>

<li>Calling remote function modules from ABAP</li>
<li>Error handling for remote calls</li>
</ul>
</div><h2 id="what-is-rfc">What Is RFC?</h2>
<p>RFC (Remote Function Call) is SAP's protocol for calling function modules on remote systems. It's how SAP systems talk to each other and how external programs call into SAP.</p>
<pre><code>System A (Development)                    System B (Production)
┌───────────────────┐                    ┌───────────────────┐
│ CALL FUNCTION      │  ── RFC call ──>  │ Z_GET_CUSTOMER    │
│  'Z_GET_CUSTOMER'  │                    │   (executes here) │
│  DESTINATION 'PRD' │  &#x3C;── response ──  │   (returns data)  │
└───────────────────┘                    └───────────────────┘
</code></pre>
<p>For a function module to be called via RFC, it must be marked as <strong>Remote-Enabled</strong> in SE37.</p>
<h2 id="rfc-destinations-sm59">RFC Destinations (SM59)</h2>
<p>RFC destinations are configured in transaction SM59. They define where a remote call goes:</p>
<pre><code>Destination Name    Type    Target System       Description
────────────────    ─────   ──────────────     ──────────────────
RFC_PRODUCTION      3       PRD (SAP system)    Production system
RFC_QUALITY         3       QAS (SAP system)    Quality system
RFC_CRM             3       CRM (SAP system)    CRM system
SAPHTTP_DEST        G       https://api.com     HTTP connection
</code></pre>
<p><strong>Connection Type 3</strong> = ABAP-to-ABAP (SAP system to SAP system)
<strong>Connection Type G</strong> = HTTP/HTTPS (SAP to external web service)</p>
<p>You typically don't create RFC destinations — the Basis team does. But you need to know the destination name to use in your code.</p>

<p>aRFC is used when you don't need the result immediately — for example, sending notifications, triggering background processes, or parallel processing.</p>
<h2 id="transactional-rfc-trfc">Transactional RFC (tRFC)</h2>
<p>Guarantees exactly-once delivery — if the remote system is down, SAP retries automatically:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">CALL</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> FUNCTION</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'Z_UPDATE_REMOTE_STATUS'</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  IN</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> BACKGROUND</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TASK</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  DESTINATION</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'RFC_PRODUCTION'</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  EXPORTING</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    iv_order_id </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">=</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> '0000100001'</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">    iv_status   </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">=</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'SHIPPED'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">COMMIT</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> WORK</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Required — sends all queued tRFC calls</span></span></code></pre>
<p><code>IN BACKGROUND TASK</code> queues the call. <code>COMMIT WORK</code> sends it. If the remote system is temporarily unavailable, SAP stores the call and retries. You can monitor pending tRFC calls in transaction SM58.</p>

<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Not handling communication_failure and system_failure.</strong> Remote calls can fail because the network is down, the remote system is offline, or credentials are wrong. Always handle these exceptions — without them, your program crashes with a short dump.</li>
<li><strong>Forgetting COMMIT WORK after tRFC calls.</strong> <code>IN BACKGROUND TASK</code> queues the call but doesn't send it. <code>COMMIT WORK</code> triggers the actual send. Without it, queued calls are lost.</li>
<li><strong>Assuming the same performance as local calls.</strong> RFC calls go over the network — they're 10-100x slower than local function calls. Don't put RFC calls inside loops. Batch data and make one RFC call with a table parameter.</li>
<li><strong>Hardcoding destination names.</strong> Store destination names in a configuration table, not in code. Destinations differ between development and production systems.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>RFC is SAP's protocol for cross-system function calls — ABAP-to-ABAP or ABAP-to-external.</li>
<li>sRFC (synchronous) = wait for result. aRFC (asynchronous) = fire and forget. tRFC (transactional) = guaranteed delivery.</li>
<li>RFC destinations are configured in SM59. Always handle <code>communication_failure</code> and <code>system_failure</code> exceptions.</li>
<li>tRFC requires COMMIT WORK to actually send the queued calls.</li>
<li>Never put RFC calls in loops — batch your data and make one call.</li>
</ul>
