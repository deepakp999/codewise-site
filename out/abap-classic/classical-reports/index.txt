<h2 id="when-to-use-classical-reports">When to Use Classical Reports</h2>
<p>Classical WRITE-based reports are simple and fast to build. Use them for:</p>
<ul>
<li>Quick ad-hoc reports</li>
<li>Simple list output</li>
<li>Debugging (writing intermediate values)</li>
<li>Legacy maintenance (many existing reports use this style)</li>
</ul>
<p><strong>For professional reports, use ALV</strong> (next lesson). ALV provides sorting, filtering, column reordering, export to Excel, and a modern look — all built in. Classical reports require you to code all of this manually.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Not setting LINE-SIZE.</strong> Default line width is 83 characters — too narrow for most reports. Use <code>LINE-SIZE 120</code> or <code>LINE-SIZE 200</code> in the REPORT statement.</li>
<li><strong>Hardcoding column positions that overlap.</strong> If you put name at position 15 and department at position 30, a name longer than 15 characters bleeds into the department column. Test with long values.</li>
<li><strong>Forgetting NO STANDARD PAGE HEADING.</strong> By default, SAP adds its own page header (program name, page number). If you use TOP-OF-PAGE for custom headers, add <code>NO STANDARD PAGE HEADING</code> to the REPORT statement to suppress the default.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Classical reports use WRITE with column positions for formatted output.</li>
<li>ULINE draws horizontal lines. SKIP adds blank lines. COLOR adds background highlighting.</li>
<li>TOP-OF-PAGE creates page headers. LINE-SIZE sets the output width.</li>
<li>For professional output, use ALV reports (next lesson) instead of classical WRITE.</li>
<li>Classical reports are still useful for debugging and quick ad-hoc output.</li>
</ul>
