1b:Ta5e8,<h1 id="subroutines-function-modules-and-methods">Subroutines, Function Modules, and Methods</h1>
<div data-cw-section="learn-box"><h2 id="what-youll-learn">What You'll Learn</h2>
<ul>
<li>FORM/PERFORM — the legacy approach (still everywhere in existing code)</li>
<li>Function modules (SE37) — SAP's reusable building blocks</li>
<li>Classes and methods — modern OOP in ABAP</li>
<li>When to use each and what SAP recommends in 2026</li>
</ul>
</div><h2 id="three-eras-of-abap-modularization">Three Eras of ABAP Modularization</h2>
<p>ABAP evolved over 40 years. Each era introduced a new way to organize code:</p>
<pre><code>1980s-1990s: FORM/PERFORM (subroutines)     — still in legacy code
1990s-2010s: Function Modules (SE37)         — SAP's standard API layer
2000s-today: Classes and Methods (SE24)      — modern ABAP, recommended
</code></pre>
<p>You need to understand all three because you'll encounter all three in real SAP systems. But for new code, always use classes and methods.</p>

<p><strong>USING</strong> passes parameters by reference (read-only intent). <strong>CHANGING</strong> passes by reference (read-write). <strong>TABLES</strong> passes internal tables.</p>
<p><strong>Coming from Python:</strong> <code>FORM</code> is like <code>def</code>, <code>PERFORM</code> is the function call. But FORM is defined below the call (unusual for most languages).</p>
<p><strong>SAP's recommendation: Don't use FORM/PERFORM in new code.</strong> It's considered obsolete. But you'll see it in thousands of existing programs.</p>
<h2 id="function-modules-se37">Function Modules (SE37)</h2>
<p>Function modules are reusable units stored in the SAP system — callable from any program, even from external systems via RFC.</p>
<p>You create them in transaction SE37 (Function Builder), not inside your program's source code. They live in <strong>function groups</strong> — containers that hold related functions.</p>

<h3 id="function-module-interface">Function Module Interface</h3>
<p>Every function module has four parameter categories:</p>
<pre><code>IMPORTING   → Input parameters (passed to the function)
EXPORTING   → Output parameters (returned from the function)
CHANGING    → Parameters that go in AND come back modified
TABLES      → Internal table parameters (legacy — use CHANGING instead)
EXCEPTIONS  → Error conditions the function can raise

<h2 id="which-approach-for-which-situation">Which Approach for Which Situation?</h2>
<pre><code>Situation                           Use
──────────────────────────────     ─────────────────────
New code in 2026                    Classes and methods
Code that must be called via RFC    Function module (RFC-enabled)
Working with SAP standard BAPIs     Function modules (they're already FMs)
Modifying legacy code               Match the existing style (usually FORM)
Quick utility in a report           Local class or static method
Reusable across programs            Global class in SE24
</code></pre>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Using FORM/PERFORM in new programs.</strong> It's tempting because it's simpler, but SAP has deprecated it. Use local classes — even a simple static method is better than a FORM.</li>
<li><strong>Forgetting exception handling on CALL FUNCTION.</strong> If a function module raises an exception you don't handle, it causes a short dump (runtime crash). Always handle EXCEPTIONS or use TRY/CATCH.</li>
<li><strong>Putting everything in PUBLIC SECTION.</strong> Like in any OOP language, minimize public methods. Use PRIVATE SECTION for internal state and helper methods.</li>
<li><strong>Confusing <code>-></code> and <code>=></code>.</strong> <code>-></code> is for instance method calls (<code>lo_object->method()</code>). <code>=></code> is for static method calls (<code>lcl_class=>method()</code>). Mixing them up causes syntax errors.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>FORM/PERFORM is legacy — read it, don't write new code with it.</li>
<li>Function modules are SAP's API layer — you'll call them constantly (BAPIs, conversions, popups).</li>
<li>Classes and methods are modern ABAP — use them for all new development.</li>
<li><code>-></code> calls instance methods, <code>=></code> calls static methods, <code>~</code> links interface methods.</li>
<li>Function module parameters use IMPORTING/EXPORTING/CHANGING/EXCEPTIONS.</li>
<li>Method parameters use IMPORTING/EXPORTING/RETURNING/CHANGING/RAISING.</li>
</ul>
