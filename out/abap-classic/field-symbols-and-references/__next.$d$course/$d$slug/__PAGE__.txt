<p>Field symbols point directly to the memory where the table row lives. Changing a field symbol changes the table — no MODIFY needed.</p>
<p><strong>Coming from Java:</strong> Field symbols are like references — <code>for (Employee emp : employees)</code> where <code>emp</code> points to the actual object, not a copy. Except in ABAP, the distinction is explicit: <code>INTO</code> = copy, <code>ASSIGNING</code> = reference.</p>
<p><strong>Coming from C:</strong> Field symbols are like pointers, but dereferenced automatically. You write <code>&#x3C;fs>-name</code>, not <code>(*fs).name</code> or <code>fs->name</code>.</p>

<p>Data references use <code>-></code> to access fields (like Java/C++ object pointers). They also modify the table directly, like field symbols.</p>
<h2 id="when-to-use-each">When to Use Each</h2>
<pre><code>Method          Performance   Modifies Table?   Best For
──────────────  ────────────  ────────────────   ───────────────────
INTO (copy)     Slower        No (need MODIFY)   Read-only access, safe
ASSIGNING (fs)  Fastest       Yes (direct)        Modifying table in loops
REFERENCE INTO  Fast          Yes (direct)        Passing to methods, dynamic programming
</code></pre>
<p><strong>Rule of thumb:</strong></p>
<ul>
<li><strong>Reading only?</strong> Use <code>INTO</code> — it's safest, no accidental modifications</li>
<li><strong>Modifying in a loop?</strong> Use <code>ASSIGNING</code> — fastest, no copy overhead</li>
<li><strong>Passing to methods or storing for later?</strong> Use <code>REFERENCE INTO</code></li>
</ul>

<h2 id="performance-example">Performance Example</h2>
<p>On a table with 100,000 rows:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* SLOW — copies every row</span></span>

<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">  ls_row-status </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">=</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'X'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  MODIFY</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> lt_big_table </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">FROM</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ls_row.  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Two operations: copy + write back</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">ENDLOOP</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* FAST — modifies in place</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">LOOP AT</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> lt_big_table </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">ASSIGNING</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> FIELD-SYMBOL</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">&#x3C;ls_row></span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">).</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">  &#x3C;ls_row></span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">-status </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">=</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'X'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" One operation: direct access</span></span>

<p>The field symbol version is roughly 2x faster because it avoids copying each row and the MODIFY write-back.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Modifying a work area and forgetting to MODIFY back.</strong> <code>LOOP AT ... INTO ls_work. ls_work-field = 'X'.</code> doesn't change the table — you need <code>MODIFY lt_table FROM ls_work.</code> Field symbols don't have this problem.</li>
<li><strong>Using a field symbol after the table is cleared.</strong> If you <code>CLEAR lt_table</code> while a field symbol still points to a row, the field symbol becomes unassigned. Accessing it causes a runtime error.</li>
<li><strong>Confusing <code>&#x3C;fs>-field</code> and <code>lr->field</code> syntax.</strong> Field symbols use <code>-</code> (dash): <code>&#x3C;ls_emp>-name</code>. Data references use <code>-></code> (arrow): <code>lr_emp->name</code>. Mixing them up causes syntax errors.</li>
<li><strong>Using generic field symbols (<code>TYPE any</code>) when typed ones work.</strong> Generic field symbols bypass type checking — you lose compile-time safety. Always use the specific type when you know it.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>INTO copies the row (safe but slower). ASSIGNING points to it (fast, modifies directly). REFERENCE INTO stores a pointer.</li>
<li>Use field symbols (<code>ASSIGNING</code>) in loops where you modify data — 2x faster than copy + MODIFY.</li>
<li>Use work areas (<code>INTO</code>) when you only read data or need a safe copy.</li>
<li>Field symbols use <code>&#x3C;angle_brackets></code> and <code>-</code> for field access. Data references use <code>-></code>.</li>
<li>Always check <code>IS ASSIGNED</code> for field symbols, <code>sy-subrc</code> for work areas.</li>
<li>Inline declaration (<code>FIELD-SYMBOL(&#x3C;ls_emp>)</code>) in loops is the cleanest modern syntax.</li>
</ul>
