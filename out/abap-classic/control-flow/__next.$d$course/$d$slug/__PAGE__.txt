<p><strong>Coming from Python:</strong> This is like <code>for emp in employees if emp.department == 'Engineering':</code> — but the filtering happens at the loop level, not as a separate filter step.</p>
<h2 id="control-statements-summary">Control Statements Summary</h2>
<pre><code>ABAP              Python              Java
──────────────     ──────────────     ──────────────
IF ... ENDIF       if:                if { }
ELSEIF             elif:              else if { }
CASE ... ENDCASE   match/case:        switch { }
DO n TIMES         for i in range(n)  for (i=0; i&#x3C;n; i++)
WHILE ... ENDWHILE while:             while { }
LOOP AT ... ENDLOOP for x in list:    for (x : list)
EXIT               break              break
CONTINUE           continue           continue
CHECK              (no equivalent)    (no equivalent)
</code></pre>
<h3 id="check--abaps-unique-control-statement">CHECK — ABAP's Unique Control Statement</h3>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DO</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> 10</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TIMES</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  CHECK</span><span style="--shiki-light:#005CC5;--shiki-dark:#E5C07B"> sy</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">-</span><span style="--shiki-light:#005CC5;--shiki-dark:#E5C07B">index</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> MOD</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> 2</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> =</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> 0</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Only continue if index is even</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  WRITE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">/</span><span style="--shiki-light:#005CC5;--shiki-dark:#56B6C2"> |</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">Even: </span><span style="--shiki-light:#005CC5;--shiki-dark:#56B6C2">{ </span><span style="--shiki-light:#032F62;--shiki-dark:#98C379">sy-index</span><span style="--shiki-light:#005CC5;--shiki-dark:#56B6C2"> }|</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">ENDDO</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span></code></pre>
<div data-cw-section="output-block"><h3 id="expected-output-8">Expected Output</h3>
<pre data-cw-output="true"><code>Even: 2
Even: 4
Even: 6
Even: 8
Even: 10
</code></pre></div>
<p><code>CHECK</code> evaluates a condition — if true, execution continues. If false, it skips to the next iteration (like <code>CONTINUE</code> with a built-in IF). It's compact but can be hard to read. Many teams prefer explicit <code>IF/CONTINUE</code> instead.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Forgetting ENDIF, ENDDO, ENDWHILE, ENDCASE.</strong> Every block opener needs its closer. The ABAP editor's syntax check (Ctrl+F2) catches these immediately, but they're still the #1 syntax error for newcomers.</li>
<li><strong>Using <code>=</code> for comparison in ambiguous contexts.</strong> <code>IF lv_x = lv_y.</code> is a comparison. <code>lv_x = lv_y.</code> outside an IF is an assignment. This is clear to ABAP developers but confuses Python developers who use <code>==</code> for comparison.</li>
<li><strong>Forgetting that DO/WHILE loops without EXIT can run forever.</strong> Unlike Python which has no <code>DO</code> loop, ABAP's <code>DO.</code> without <code>TIMES</code> runs indefinitely. Always have an <code>EXIT</code> condition.</li>
<li><strong>Using <code>sy-index</code> outside a DO loop.</strong> <code>sy-index</code> is the DO loop counter. Inside a <code>LOOP AT</code>, use <code>sy-tabix</code> instead. Using the wrong system variable is a common source of bugs.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li><code>IF/ELSEIF/ELSE/ENDIF</code> and <code>CASE/WHEN/ENDCASE</code> handle branching.</li>
<li><code>DO n TIMES</code> for counted loops, <code>WHILE</code> for conditional loops, <code>LOOP AT</code> for iterating tables.</li>
<li><code>sy-index</code> = current DO loop counter. <code>sy-tabix</code> = current LOOP AT row index. Both are 1-based.</li>
<li><code>EXIT</code> = break, <code>CONTINUE</code> = skip to next iteration, <code>CHECK</code> = conditional continue.</li>
<li><code>IS INITIAL</code> checks for default values — ABAP's way of checking "empty" or "unset."</li>
<li>Every block ends with <code>END*</code> — ENDIF, ENDDO, ENDWHILE, ENDCASE, ENDLOOP.</li>
</ul>
