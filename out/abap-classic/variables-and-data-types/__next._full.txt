<p><strong>Coming from Python:</strong> In Python you write <code>name = "Alice"</code> — no type declaration needed. ABAP requires explicit types: <code>DATA lv_name TYPE string.</code> then <code>lv_name = 'Alice'.</code> This is closer to Java's <code>String name = "Alice";</code> but even more verbose.</p>

<p><strong>When to use which:</strong></p>
<ul>
<li><code>i</code> — counters, loop indexes, quantities (whole numbers)</li>
<li><code>p</code> — money, financial calculations (exact decimals, no rounding errors)</li>
<li><code>f</code> — scientific calculations (rare in business applications)</li>
<li><code>int8</code> — very large whole numbers</li>
</ul>
<p><strong>Critical rule:</strong> Never use <code>f</code> (float) for financial data. Use <code>p</code> (packed decimal). <code>0.1 + 0.2</code> in floating point doesn't equal <code>0.3</code> — this matters when your report is for a CFO.</p>

<p><strong><code>c</code> vs <code>string</code>:</strong> Use <code>c</code> (fixed-length) when the data always has the same length — country codes (2 chars), material numbers (18 chars), plant codes (4 chars). Use <code>string</code> for free text — names, descriptions, addresses.</p>

<p>Inline declarations are cleaner, but classic <code>DATA</code> statements are still used everywhere — especially at the top of programs where you declare all variables before the logic begins.</p>
<h2 id="the-type-keyword--referencing-dictionary-types">The TYPE Keyword — Referencing Dictionary Types</h2>
<p>You can declare variables using types from the SAP Data Dictionary:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* Using SAP standard types from the data dictionary</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DATA</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: lv_customer_id</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TYPE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> kunnr,     </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Customer number (from SAP standard)</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">      lv_material   </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TYPE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> matnr,     </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Material number</span></span>
<span class="line"><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">      lv_amount     </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TYPE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> netwr_ap.  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Net value (currency amount)</span></span>
<span class="line"></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* Using a structure from a database table</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DATA</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: ls_customer</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TYPE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> kna1.  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" Structure with ALL fields of table KNA1</span></span></code></pre>
<p>This is a powerful concept — instead of defining <code>TYPE c LENGTH 10</code>, you reference the SAP-defined type <code>kunnr</code> (customer number). If SAP ever changes the length of customer numbers, your code automatically adapts.</p>

<h2 id="type-conversion">Type Conversion</h2>
<p>ABAP converts between compatible types automatically, but you should be explicit:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DATA</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: lv_number</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TYPE</span><span style="--shiki-light:#005CC5;--shiki-dark:#ABB2BF"> i</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> VALUE</span><span style="--shiki-light:#005CC5;--shiki-dark:#D19A66"> 42</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">,</span></span>

<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Using <code>f</code> (float) for currency amounts.</strong> Always use <code>p DECIMALS 2</code> for money. Floating-point arithmetic has rounding errors: <code>0.1 + 0.2 = 0.30000000000000004</code>. Packed decimal is exact.</li>
<li><strong>Forgetting that <code>c</code> type is space-padded.</strong> A <code>TYPE c LENGTH 10</code> variable containing <code>'Hello'</code> actually contains <code>'Hello     '</code> (5 chars + 5 spaces). Comparisons and concatenations can produce unexpected results if you don't trim.</li>
<li><strong>Not initializing variables.</strong> Unlike Python, ABAP initializes variables to type-specific defaults: <code>i</code> = 0, <code>string</code> = '' (empty), <code>d</code> = '00000000'. But relying on defaults makes code unclear — always set initial values explicitly when they matter.</li>
<li><strong>Confusing <code>n</code> and <code>i</code> types.</strong> <code>TYPE n LENGTH 4</code> is text that looks like a number — <code>'0042'</code> preserves the leading zero. <code>TYPE i</code> is an actual integer — <code>42</code>. Use <code>n</code> for document numbers and codes, <code>i</code> for calculations.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Declare variables with <code>DATA</code>, constants with <code>CONSTANTS</code>. Use meaningful prefixes (<code>lv_</code>, <code>lc_</code>, <code>lt_</code>).</li>
<li>Use <code>p DECIMALS n</code> for financial calculations, <code>i</code> for whole numbers, <code>string</code> for free text.</li>
<li><code>TYPE d</code> stores dates as <code>YYYYMMDD</code>, <code>TYPE t</code> stores times as <code>HHMMSS</code>.</li>
<li><code>sy-subrc</code> is checked after every operation — 0 means success.</li>
<li>Inline declarations (<code>DATA(lv_x) = ...</code>) are modern ABAP — cleaner but not universal yet.</li>
<li>Reference SAP Data Dictionary types (<code>TYPE kunnr</code>, <code>TYPE matnr</code>) instead of raw types when working with SAP data.</li>
</ul>
