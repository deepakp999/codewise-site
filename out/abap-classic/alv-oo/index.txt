<h2 id="reuse-vs-cl_salv--when-to-use-which">REUSE vs CL_SALV — When to Use Which</h2>
<pre><code>Feature                    REUSE_ALV    CL_SALV_TABLE
─────────────────────────  ──────────   ─────────────
Approach                   Function     OOP
Field catalog              Manual       Auto-generated
Column customization       Via table    Via methods
Event handling             FORM/PERFORM Class events
Editable grid              Yes          Limited
Recommended for new code   No           Yes
Learning curve             Lower        Moderate
</code></pre>
<p><strong>For new programs, use CL_SALV_TABLE.</strong> It's cleaner, more maintainable, and SAP's recommended approach. Use REUSE_ALV only when maintaining existing code that already uses it, or when you need editable grid functionality.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Forgetting <code>get_functions( )->set_all( )</code>.</strong> Without it, the ALV toolbar is minimal — users can't sort, filter, or export. Always call <code>set_all()</code> unless you have a specific reason to restrict functions.</li>
<li><strong>Not handling exceptions.</strong> CL_SALV methods throw exceptions for invalid column names, duplicate sorts, etc. Always wrap in TRY/CATCH.</li>
<li><strong>Trying to make CL_SALV_TABLE editable.</strong> CL_SALV_TABLE is designed for display, not editing. For editable grids, you need CL_GUI_ALV_GRID (more complex) or the REUSE function module approach.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>CL_SALV_TABLE is the modern OOP approach to ALV — cleaner than REUSE_ALV_GRID_DISPLAY.</li>
<li><code>factory()</code> creates the ALV, method calls customize it, <code>display()</code> shows it.</li>
<li>Call <code>get_functions()->set_all()</code> to enable all toolbar features.</li>
<li>Use <code>get_columns()</code> to customize individual columns.</li>
<li>Use <code>get_sorts()</code> for sorting and <code>get_aggregations()</code> for totals.</li>
<li>Always wrap in TRY/CATCH — CL_SALV methods throw exceptions.</li>
</ul>
