</div><h2 id="open-sql-vs-native-sql">Open SQL vs Native SQL</h2>
<p>ABAP uses <strong>Open SQL</strong> — a database-independent SQL dialect. Your SELECT statements work on any database SAP supports (HANA, Oracle, DB2, SQL Server). The ABAP runtime translates Open SQL into the native SQL of your specific database.</p>
<p>This means you write one SELECT, and it works everywhere. The trade-off: Open SQL doesn't support every SQL feature (no window functions in classic ABAP, for example). Modern ABAP on HANA loosens this through CDS views (Course 2).</p>

<h2 id="for-all-entries--abaps-unique-bulk-lookup">FOR ALL ENTRIES — ABAP's Unique Bulk Lookup</h2>
<p>This is one of ABAP's most distinctive features — and one of its most dangerous.</p>
<p><strong>Problem:</strong> You have a list of customer IDs and need their details from KNA1. In SQL, you'd use <code>WHERE kunnr IN (subquery)</code>. In ABAP, you use FOR ALL ENTRIES.</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* Step 1: Get some order data</span></span>

<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">  INTO TABLE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> @</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DATA</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">(</span><span style="--shiki-light:#24292E;--shiki-dark:#E06C75">lt_orders</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">)</span></span>

<span class="line"></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* Step 2: Get customer details for those orders</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">IF</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> lt_orders </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">IS</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> NOT</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> INITIAL</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.  </span><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">" CRITICAL — never use FAE with empty table!</span></span>

<p><strong>Performance note:</strong> ORDER BY in Open SQL sorts at the database level, which is efficient. But if you're going to process the data further in ABAP anyway, it's sometimes faster to sort the internal table in memory with <code>SORT</code>.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Using FOR ALL ENTRIES with an empty driver table.</strong> This returns ALL records from the target table. Always wrap with <code>IF lt_driver IS NOT INITIAL.</code></li>
<li><strong>Using SELECT * in production code.</strong> Reading all 200 columns of BSEG when you need 5 wastes database I/O, network bandwidth, and memory. Always specify the fields you need.</li>
<li><strong>Not checking sy-subrc after SELECT SINGLE.</strong> If the record doesn't exist, your work area contains old data from the previous read. Always check <code>sy-subrc = 0</code>.</li>
<li><strong>Putting SELECT inside a LOOP.</strong> <code>LOOP AT lt_orders. SELECT FROM kna1 WHERE kunnr = ls_order-kunnr. ENDLOOP.</code> executes one database call per row — extremely slow on large tables. Use FOR ALL ENTRIES or a JOIN instead.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Use <code>SELECT SINGLE</code> for one record, <code>SELECT ... INTO TABLE</code> for multiple records.</li>
<li>Always specify needed fields — never <code>SELECT *</code> in production.</li>
<li>FOR ALL ENTRIES is powerful but dangerous — always check the driver table is not empty.</li>
<li>Use JOINs when you need related data from multiple tables in one query.</li>
<li>Never put SELECT inside a LOOP — use FOR ALL ENTRIES or JOINs for bulk lookups.</li>
<li>Always check <code>sy-subrc</code> after SELECT SINGLE.</li>
</ul>
