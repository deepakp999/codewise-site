<ul>
<li>How SAP stores data in the underlying database</li>
<li>What transparent tables are and why they matter</li>
<li>Primary keys and foreign keys in SAP</li>
<li>Table categories: transparent, pooled, and cluster</li>
<li>How to view table data with SE16N</li>
</ul>
</div><h2 id="transparent-tables">Transparent Tables</h2>
<p>A <strong>transparent table</strong> is the most common table type in SAP. It has a 1:1 mapping between the dictionary definition in SE11 and the actual database table — same name, same fields, same structure.</p>
<pre><code>SE11 Definition: ZEMPLOYEES          Database Table: ZEMPLOYEES
┌──────────────┬──────────────┐     ┌──────────────┬──────────────┐
│ MANDT (key)  │ CLNT(3)      │     │ MANDT        │ VARCHAR(3)   │
│ EMP_ID (key) │ NUMC(10)     │     │ EMP_ID       │ VARCHAR(10)  │
│ NAME         │ CHAR(50)     │     │ NAME         │ VARCHAR(50)  │
│ DEPARTMENT   │ CHAR(30)     │     │ DEPARTMENT   │ VARCHAR(30)  │
│ SALARY       │ CURR(13,2)   │     │ SALARY       │ DECIMAL(13,2)│
└──────────────┴──────────────┘     └──────────────┴──────────────┘
        Dictionary                         Database
</code></pre>
<p>What you define in SE11 is what exists in the database. When you activate a table in SE11, SAP creates (or alters) the corresponding database table automatically.</p>
<h2 id="primary-keys">Primary Keys</h2>
<p>Every SAP table has a primary key. The first key field is almost always MANDT (client). The remaining key fields uniquely identify a record within that client.</p>
<pre><code>Table KNA1 (Customer Master):
  Primary Key: MANDT + KUNNR
  
  MANDT  KUNNR       NAME1              LAND1
  ──────────────────────────────────────────────
  100    0000001001   Acme Corp          US
  100    0000001002   Global Industries  DE
  200    0000001001   Test Customer      US     ← Same KUNNR, different client
</code></pre>
<p>The combination MANDT + KUNNR is unique. Two rows can have the same KUNNR if they're in different clients (different MANDT values). This is how client isolation works at the database level.</p>
<h2 id="foreign-keys">Foreign Keys</h2>
<p>Foreign keys define relationships between tables:</p>
<pre><code>VBAK (Sales Order Header)              VBAP (Sales Order Items)
┌────────┬────────┬────────┐          ┌────────┬────────┬────────┬────────┐
│ MANDT  │ VBELN  │ KUNNR  │          │ MANDT  │ VBELN  │ POSNR  │ MATNR  │
│ 100    │ 100001 │ 001001 │───┐      │ 100    │ 100001 │ 000010 │ MAT001 │
│ 100    │ 100002 │ 001002 │   │      │ 100    │ 100001 │ 000020 │ MAT002 │
└────────┴────────┴────────┘   │      │ 100    │ 100002 │ 000010 │ MAT003 │
                               │      └────────┴────────┴────────┴────────┘
                               └──── VBELN links header to items
</code></pre>
<p>VBAK.VBELN → VBAP.VBELN — every item belongs to a header. This is a standard parent-child relationship, like orders and order_items in any e-commerce database.</p>
<h2 id="viewing-table-data-with-se16n">Viewing Table Data with SE16N</h2>
<p>Type <code>/nSE16N</code>, enter a table name, and press F8 (Execute):</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* SE16N lets you:</span></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* - View all records or filter by specific fields</span></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* - Export data to a spreadsheet</span></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* - Count records matching your criteria</span></span>
<span class="line"><span style="--shiki-light:#6A737D;--shiki-light-font-style:inherit;--shiki-dark:#7F848E;--shiki-dark-font-style:italic">* - Display individual records in detail</span></span></code></pre>
<p><strong>SE16N is your best debugging friend.</strong> When an ABAP program produces wrong results, the first question is always: "What's actually in the table?" SE16N answers that.</p>
<h3 id="useful-se16n-tricks">Useful SE16N tricks:</h3>
<ul>
<li>Enter <code>*</code> in a field to see all values</li>
<li>Enter a range like <code>001000</code> to <code>001999</code> for number ranges</li>
<li>Use the "Number of Entries" button to count without displaying all rows</li>
<li>Maximum display is 500 rows by default — change the setting if you need more</li>
</ul>
<h2 id="table-categories-in-s4hana">Table Categories in S/4HANA</h2>
<p>In modern S/4HANA, only transparent tables exist. But in older SAP systems, you'll encounter:</p>
<pre><code>Transparent Table  → 1:1 with database table (99% of what you'll work with)
Pooled Table      → Multiple SAP tables stored in one database table (legacy)
Cluster Table     → Multiple SAP tables stored in one database table, compressed (legacy)
</code></pre>
<p>Pooled and cluster tables were used for performance in older databases. S/4HANA on HANA doesn't need them — they're all converted to transparent tables during migration.</p>

<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Forgetting that MANDT is part of the key.</strong> When you select data, SAP automatically filters by the current client (sy-mandt). But if you're doing cross-client operations or debugging, remember that the same key can exist in multiple clients.</li>
<li><strong>Using SE16 to modify production data.</strong> SE16 can display and (with authorization) modify data directly. This is extremely dangerous in production — changes bypass all application logic, validation, and audit trails. Never modify production data via SE16.</li>
<li><strong>Not understanding key fields.</strong> If you try to INSERT a record with the same primary key as an existing record, it fails (sy-subrc = 4). Use MODIFY instead if you want to insert-or-update.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Transparent tables have a 1:1 mapping between SE11 definition and the database table.</li>
<li>Primary keys always include MANDT (client) as the first field.</li>
<li>Foreign keys define relationships between tables (header ↔ items, master ↔ transaction).</li>
<li>SE16N is your primary tool for viewing table data — essential for debugging.</li>
<li>In S/4HANA, all tables are transparent. Pooled and cluster tables are legacy concepts.</li>
</ul>
