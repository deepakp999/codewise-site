</div><h2 id="creating-a-program-step-by-step">Creating a Program Step by Step</h2>
<h3 id="step-1-open-se38">Step 1: Open SE38</h3>
<p>Type <code>/nSE38</code> in the command field and press Enter. You see a screen with a "Program" input field.</p>
<h3 id="step-2-name-your-program">Step 2: Name Your Program</h3>
<p>Type <code>Z_HELLO_WORLD</code> in the program field.</p>
<p>The <code>Z_</code> prefix is mandatory for custom programs (as we learned in Lesson 2). Program names can be up to 30 characters, letters, numbers, and underscores only.</p>
<h3 id="step-3-click-create">Step 3: Click "Create"</h3>
<p>SAP asks for program attributes:</p>
<ul>
<li><strong>Title:</strong> "My First ABAP Program" (free text description)</li>
<li><strong>Type:</strong> "Executable Program" (this is the most common type)</li>
<li><strong>Status:</strong> "Test Program"</li>
<li><strong>Application:</strong> leave blank or select any</li>
</ul>
<p>Click Save. SAP then asks for a <strong>package</strong> — this is where your program lives organizationally. For learning, use the <code>$TMP</code> package (local, non-transportable — it stays in DEV only and won't be transported to QAS or PRD). For real projects, you'd create a proper package.</p>
<h3 id="step-4-write-the-code">Step 4: Write the Code</h3>
<p>The editor opens. Replace any existing content with:</p>

<span class="line"></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">WRITE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">/</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'Hello, World!'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">WRITE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">/</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'This is my first ABAP program.'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>

<h3 id="step-5-check-syntax-ctrlf2">Step 5: Check Syntax (Ctrl+F2)</h3>
<p>Click the "Check" button or press Ctrl+F2. If there are no errors, the status bar at the bottom shows a green message. If there's an error, it highlights the line and shows a description.</p>
<h3 id="step-6-activate-ctrlf3">Step 6: Activate (Ctrl+F3)</h3>
<p>Click "Activate" or press Ctrl+F3. This compiles the program and makes it executable. You'll see a popup asking what to activate — select your program and confirm.</p>
<h3 id="step-7-run-f8">Step 7: Run (F8)</h3>
<p>Click "Execute" or press F8. The program runs and you see:</p>
<div data-cw-section="output-block"><h3 id="expected-output">Expected Output</h3>
<pre data-cw-output="true"><code>Hello, World!
This is my first ABAP program.
I am learning ABAP on Codewise.
</code></pre></div>
<p>Congratulations — you just ran your first ABAP program.</p>
<h2 id="understanding-the-code">Understanding the Code</h2>
<h3 id="the-report-statement">The REPORT Statement</h3>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">REPORT</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> z_hello_world.</span></span></code></pre>
<p>Every executable ABAP program starts with <code>REPORT</code>. It tells SAP: "This is a program named z_hello_world." The period at the end is required — ABAP statements end with periods, not semicolons.</p>
<h3 id="the-write-statement">The WRITE Statement</h3>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">WRITE</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: </span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">/</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'Hello, World!'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span></code></pre>
<p><code>WRITE</code> outputs text to the screen (called the "list output" in SAP terminology). Breaking it down:</p>
<ul>
<li><code>WRITE:</code> — the output command (the colon starts a chained statement)</li>
<li><code>/</code> — means "start a new line" (like <code>\n</code> in Python)</li>
<li><code>'Hello, World!'</code> — the text to display (single quotes for text literals)</li>
<li><code>.</code> — end of statement</li>
</ul>
<p>Without the <code>/</code>, everything prints on the same line:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">WRITE</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'Hello'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span>
<span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">WRITE</span><span style="--shiki-light:#032F62;--shiki-dark:#98C379"> 'World'</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">.</span></span></code></pre>

<h3 id="naming-convention-lv_-lt_-ls_-gv_-gt_-gs_">Naming Convention: lv_, lt_, ls_, gv_, gt_, gs_</h3>
<p>ABAP has a widely followed naming convention using prefixes:</p>
<pre><code>lv_   → Local Variable         (lv_name, lv_count)
lt_   → Local Table            (lt_customers, lt_orders)
ls_   → Local Structure        (ls_customer, ls_order_header)
gv_   → Global Variable        (gv_company_code)
gt_   → Global Table           (gt_all_customers)
gs_   → Global Structure       (gs_current_user)
</code></pre>
<p>This isn't enforced by the language, but every SAP shop follows it. When you see <code>lt_orders</code>, you immediately know: local variable, it's a table (list), named orders.</p>

<p><strong>Coming from Python:</strong> Python has <code>str</code>, <code>int</code>, <code>float</code>, <code>bool</code>, <code>datetime</code>. ABAP has <code>string</code>/<code>c</code>, <code>i</code>, <code>p</code>/<code>f</code>, <code>abap_bool</code>, <code>d</code>/<code>t</code>. The big difference is ABAP's <code>p</code> (packed decimal) type — used for financial calculations where floating-point imprecision is unacceptable. ABAP also has fixed-length strings (<code>c</code>), which Python doesn't.</p>

<h2 id="abap-program-types">ABAP Program Types</h2>
<p>We created an "Executable Program" (type 1). There are other types:</p>
<pre><code>Type 1  Executable Program (REPORT)  — runs directly with F8, produces list output
Type M  Module Pool                  — dialog programs with screens (less common now)
Type F  Function Group               — container for function modules
Type K  Class Pool                   — container for OOP classes
Type I  Include Program              — reusable code included in other programs
</code></pre>
<p>For this course, we'll mostly write Type 1 (executable programs). You'll encounter function groups and class pools as we progress.</p>
<h2 id="the-program-flow">The Program Flow</h2>
<p>When you press F8 to run a program, here's what happens:</p>
<ol>
<li>SAP loads your activated program from the database</li>
<li>The ABAP runtime executes statements top to bottom</li>
<li>WRITE statements build a "list buffer" (not shown yet)</li>
<li>After execution, the list buffer is displayed on screen</li>
<li>The user sees the output</li>
</ol>
<p>This is different from web development where output streams to a browser in real time. ABAP builds the complete output first, then displays it all at once.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Missing period at the end of a statement.</strong> Every ABAP statement ends with a period. Missing it causes a syntax error on the <em>next</em> line, which can be confusing — the error is actually on the line above.</li>
<li><strong>Using double quotes for text literals.</strong> ABAP uses single quotes for strings: <code>'Hello'</code> not <code>"Hello"</code>. Double quotes start inline comments: <code>WRITE 'Hello'. "This prints Hello</code>.</li>
<li><strong>Forgetting to activate before running.</strong> Save (Ctrl+S) stores your source code but doesn't compile it. You must activate (Ctrl+F3) before running (F8). If your changes aren't reflected, you forgot to activate.</li>
<li><strong>Starting a program name without Z or Y.</strong> SAP won't let you create objects without the Z/Y prefix in customer namespace. If you get a "namespace" error, check your program name.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>Every executable ABAP program starts with <code>REPORT program_name.</code></li>
<li>Statements end with periods. Comments use <code>*</code> (full line) or <code>"</code> (inline).</li>
<li><code>DATA</code> declares variables. <code>WRITE</code> outputs text. <code>/</code> starts a new line.</li>
<li>Use the naming convention: <code>lv_</code> for local variables, <code>lt_</code> for local tables.</li>
<li>The workflow is: write → check (Ctrl+F2) → activate (Ctrl+F3) → run (F8).</li>
<li>Always use the <code>$TMP</code> package for practice programs.</li>
</ul>
