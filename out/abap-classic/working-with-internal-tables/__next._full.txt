<h2 id="filter-abap-740">FILTER (ABAP 7.40+)</h2>
<p>For SORTED and HASHED tables, FILTER is the fastest way to extract subsets:</p>
<pre class="shiki shiki-themes github-light one-dark-pro" style="--shiki-light:#24292e;--shiki-dark:#abb2bf;--shiki-light-bg:#fff;--shiki-dark-bg:#282c34" tabindex="0"><code><span class="line"><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD">DATA</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF">: lt_sorted</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> TYPE SORTED TABLE OF</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> ty_employee</span><span style="--shiki-light:#D73A49;--shiki-dark:#C678DD"> WITH NON-UNIQUE KEY</span><span style="--shiki-light:#24292E;--shiki-dark:#ABB2BF"> department.</span></span>

<p>FILTER uses the table's key for efficient lookup — it's faster than LOOP AT with WHERE on sorted/hashed tables.</p>
<div data-cw-section="mistake-card"><h2 id="common-mistakes">Common Mistakes</h2>
<ul>
<li><strong>Modifying a table while looping over it without care.</strong> Deleting rows inside a <code>LOOP AT</code> changes the table size, causing skipped rows. Use <code>DELETE WHERE</code> outside the loop, or loop backward.</li>
<li><strong>Forgetting that SORT modifies the table in place.</strong> Unlike Python's <code>sorted()</code> which returns a new list, ABAP's <code>SORT</code> changes the original table. If you need the original order preserved, copy the table first.</li>
<li><strong>Using COLLECT with non-numeric character fields as keys.</strong> COLLECT matches rows by comparing all non-numeric fields. If your "key" includes a string that varies slightly (trailing spaces, case differences), you'll get unexpected duplicate rows instead of aggregation.</li>
<li><strong>Assuming FOR expressions work on STANDARD tables with WHERE.</strong> The WHERE clause in FOR works on all table types, but FILTER (more efficient) requires SORTED or HASHED keys.</li>
</ul>
</div><h2 id="key-takeaways">Key Takeaways</h2>
<ul>
<li>MODIFY updates rows by index, condition, or work area. Use TRANSPORTING to update specific fields only.</li>
<li>DELETE removes by index or WHERE condition. DELETE ADJACENT DUPLICATES needs a sorted table.</li>
<li>SORT modifies the table in place — sort by multiple fields with ASC/DESC.</li>
<li>COLLECT auto-aggregates numeric fields for matching non-numeric keys — ABAP's in-memory GROUP BY.</li>
<li>CORRESPONDING copies fields with matching names between structures.</li>
<li>FOR expressions are ABAP's list comprehensions. FILTER is optimized for sorted/hashed tables.</li>
</ul>
